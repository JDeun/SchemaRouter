# Gate A — prior art, baseline and architecture decision

Date: 2026-11-27. Parent #1897; gate #1898; next #1899. Requirements: [PRD v0.1](PRD.md), especially sections 3, 7 and 8.

## Decision (ADR-001)

**REUSE standard RDF and SPARQL for the first isolated PoC.** Start from RDFLib 7.5.0, the version actually executed in the baseline. Keep the backend provisional until the full PoC validates the contract. Do not implement a custom graph database, reasoning engine, tool ranker, internal LLM, planner or executor. RDFLib is the current baseline and the starting implementation, not a new product differentiation arm.

The minimal potential product is a source-schema/semantic-annotation normalization and validated agent-facing partial-schema adapter around an existing ontology stack. If that is just baseline C, run it as C in #1900; do not invent a separate D or claim an algorithmic advantage. Product differentiation, real-agent utility and independent confirmation remain open.

## Executed baseline (C)

[ontology_baseline.py](ontology_baseline.py) is a 154-line isolated research control with four synthetic source schemas and declared concept/alias mappings. All arms must use the same metadata/permissions; the source manifest is embedded here and now published as a public synthetic DEV sample, not a real provider catalog. It does not access the historical private paper or use a model.

- Graph: Tool -> Endpoint -> ResponseField -> Concept -> declared alias; input parameter links; source schema and source revision stored; synthetic unit/source/license metadata kept. SPARQL returns matching endpoints/field names. Projection copies the original input schema unchanged and builds a flat output view with matching fields and identifiers.
- Actual local runtime: Python 3.13.5, RDFLib 7.5.0, pyparsing 3.3.2, jsonschema 4.26.0. Direct dependencies pinned in [requirements-baseline.txt](requirements-baseline.txt); not a full transitive lockfile.
- Run from this directory: `python -m pip install -r requirements-baseline.txt`, then `python ontology_baseline.py -v`. Executed using already-installed packages, not a fresh dependency install. Local source Git blob `70d15a305fec5c00f60cb333eeddd18a848378f6` matches checked-in [commit b5423d3](https://github.com/JDeun/SchemaRouter/commit/b5423d3d2b9ad603e03d3ceee3e093ee839c8fa8). All six unittest cases passed locally.
- Cases: two independent needs and alternative endpoints with same concept, ambiguity/uncovered, persist/reload, 8 matching routes (no fixed top-five), unsupported nested output rejection, prepermitted source surface.
- Observed 71 RDF triples. For the two-need request: four total routes, three matching routes, 12 total response fields, 10 fields on matching full schemas, 7 projected fields including identifiers. Both declared requirements matched. These are synthetic counts, **not** token savings, answer accuracy, generalized recall or performance measurements.

### Boundaries and next implementation work

Only a restricted flat string/number output schema subset is supported. JSON Schema syntax validation is not proof of arbitrary invocation compatibility. The output view is separate from the original provider output contract; the input contract is copied, not reduced. No nested projection, source-format adapter, actual provider metadata, dynamic per-field authorization, general lifecycle/update/delete, field-group inference or comprehensive ontology version is implemented. The source hash covers the individual manifest, not an independently versioned complete ontology. No performance/scale test or real agent run. Do not expose the demo as a production API.

#1899 must evaluate the WoT vocabulary mapping/reuse and establish the minimal versioned contract, lifecycle, safe projection and required inputs/ref closure (FR-01–FR-09, AC-01–AC-10). Prefer a small wrapper on existing technology; do not create another general-purpose engine. Use the same baseline and exposed public 19-source/166-field historical inventory only as development evidence; no private keys, new release, or old core imports. #1900 owns independent same-agent comparative utility and project Go/No-Go.
