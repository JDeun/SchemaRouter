# Durable, operator-issued in-band provider GET allowance — SQLite E1

## Scope

The existing #1628–#1630 source-native in-band Open-Meteo canary **one-shot** is real public read-only API traffic, but its fixed per-callback counter is Python process-local: restarting a process creates a new `InBandCanaryCallbacksE1` and can incorrectly treat its own new counter as fresh approval. Multiple workers on ONE host can also race to exceed a per-source budget unless they share an atomic owner. This E1 is a **separate opt-in research wrapper**, not a production switch, that makes an explicitly operator-issued finite budget persistent in a single, trusted **local** SQLite file.

## Narrow design and limits

- The operator must supply an **absolute `.sqlite3` path in an existing trusted local directory**, `operator_approved=True`, expiry duration 1–3600 seconds, and per-native-route maximum 1–2 attempts. Only an explicit `initialize()` creates the lease. A second initialize on the same lease **fails**, even after exhaustion or expiry. A background watcher never creates or renews authorization.
- Use SQLite `BEGIN IMMEDIATE` inside separate connections for shared-host cross-process/thread serialization. There is ONE bounded lease `open_meteo_inband_canary_e1`, original `open_meteo_geocoding.search` and `open_meteo_weather.current` counts, absolute UTC expiry and last-seen wall time. `try_claim` connects in **mode=rw** only; missing/removed/corrupted DB, malformed route, exhausted quota, expired lease or regressed wall clock all fail closed. Per-source reservations are **atomic and nonrefundable**: even if the downstream public API times out or the process exits, its allowance remains spent. No implicit or automatic refund.
- `wrap_probe(route, original_fixed_native_canary)` provides a callback to the **existing `AccessHealthMonitor`**, reserving its allowance **BEFORE** invoking the already-approved `InBandCanaryCallbacksE1` source parser. A failed claim returns False (unhealthy/temporarily unavailable) with ZERO additional business GET. Existing source scope, `HealthProbeSnapshot` registration epoch, cooldown, original binding and allowed-only native GET transport must remain mandatory. No LLM/model action can allocate a lease.
- This is **same-host/same-file** coordination only, *NOT* shared across separate machines, independent Kubernetes replicas, HA storage, container ephemeral volumes or networked filesystems. It does not protect a malicious file owner who deletes/replaces the SQLite DB; the trust boundary is that the operator controls a stable, non-symlink path and durable filesystem backup/ACL. Clock rollback is rejected, but this is not a tamper-proof time source and time changes are a documented limitation.
- Do not call real provider APIs to test quotas: the dedicated E1 CI uses offline `httpx.MockTransport` for actual original source-specific response validation, concurrent independent SQLite connections, a process-simulated new router + new callback instance, expiry/rollback and missing/corrupt DB. Absolutely **no new external GET traffic** is authorized. Existing public source one-shot stays opt-in/off by default.
- The `public_counts()` receipt exposes aggregate geocoding/forecast spent amounts only, never a local path, lease token or provider payload. No process-global renewal, automated quota refresh, cloud lock, production SLO, actual Open-Meteo downtime, independent E2 or commercial free-tier entitlement is claimed.

## Production follow-up

A deployed multihost service needs a separately approved **central atomic durable lease service**, identity/principal-bound issuance, durable operator revocation, rotation/expiry and race-tested failure modes, secure storage permissions and explicit provider terms/rate limits. Those items remain OPEN on #1618. v0.18 #1356 HARD HOLD, original frozen #432 preserved.


## E1 follow-up: irreversible same-host operator revocation

The first merged #1631 SQLite lease had finite expiration and no silent refill, but lacked a way for an operator to cancel still-unspent approved health-canary allowance. The new **explicit** `revoke(operator_approved=True)` uses the SAME `BEGIN IMMEDIATE` transaction as probe reservations and changes `expires=issued` within the original schema, permanently preventing subsequent `try_claim` calls for **both** native sources. The sentinel is deliberately non-renewable even after a worker restart; no new schema or automatic quota rollover. Repeated revocations return False, indicating the allowance was already revoked.

The new `revoke_and_reconcile(existing_router, operator_approved=True)` commits the durable cancellation from an off-event-loop SQLite worker and then **replaces precisely the two original read-only route health probes on that Router with a local deny callback** before invoking `check_health_once()`. This is intentionally safer than re-running previously registered callbacks: a misconfigured Router might have an unwrapped external business GET probe, which must never be invoked after an operator stop. The resulting health status epoch rejects an older Healthy model-menu receipt, and subsequent tool visibility is `temporary_unavailable` with no route; this one Router's callbacks remain locally denied until a separately trusted re-registration. Tests assert zero post-revocation calls even for incorrectly unwrapped callbacks, same-router receipt invalidation, independent OS processes blocked after revocation, restart persistence, wall-clock rollback, concurrent claim/revoke races, no-operator rejection, corrupted/absent DB, and sanitized receipts—all via local SQLite and MockTransport, with ZERO external network requests.

**Important non-claim:** This is **not instant global revocation**. An API request whose attempt was already reserved before revocation is *not forcibly interrupted*. Other active routers, even when they share the SQLite file, must each explicitly recheck their monitor (or wait for their next normal health tick); a cached Healthy menu on another process remains possibly visible until then. It does not provide a distributed atomic fence between approval revocation and canonical endpoint execution. For production-critical instantaneous revocation, the trusted executor would need a separate coordinator-backed execution-time authorization check and a distributed lease/revocation epoch. Such controls and actual provider quota licensing remain unresolved #1618 gates.

Only the opt-in E1 SQLite budget adapter is changed. The original read-only source's business call, product defaults, publisher-independent E2 and frozen #432 are unchanged; v0.18 #1356 HARD HOLD remains.


## 2026-10-21 strict E1: cross-router cached Healthy withdrawal on revoked shared approval

The previous #1634 local revocation helper refreshes only its *own* Router; a separate Router in the same shared-host SQLite lease domain may retain a model-visible Healthy receipt until its next background sweep. In the actual #1635 one-shot source runner, that could allow its **dependent weather business GET** after another local process had revoked the canary allowance during the first native geocoding GET.

The optional `approval_active()` is a **read-only, no-GET, non-consuming** SQLite validity check: missing/corrupt/revoked/expired/rolled-back-clock lease fails closed while a merely spent probe allowance still permits a previously verified healthy receipt until its normal freshness expiry. `reconcile_if_approval_invalid(existing_router)` checks that shared file before route publication/dispatch. On invalidity, it replaces the two original trusted E1 health registrations with local deny callbacks and refreshes the existing monitor, invalidating any prior Healthy model-visible receipt with **zero additional provider probe GET**. The original runner checks again before native invocation and before its dependent weather route is displayed.

Deterministic offline witness: two separately instantiated original routers with different callback objects and the same SQLite lease each become healthy; an external controller revokes the lease, and the untouched second router's cached Healthy menu becomes unavailable after its explicit read-through refresh without sending a new GET. A second original MockTransport runner witness revokes during the first real geocoding *business* GET and prevents the second weather business GET (three already-authorized GETs total: two canaries + one geocode).

**Not claimed:** This is *not* automatic cross-process notification; a host must invoke the explicit read-through check on the active routing path. The check-to-network race and already in-flight GET remain, and neither SQLite read-through nor monitor callback replacement is an atomic remote execution-time revocation fence. Untrusted model text cannot create an operator lease or assert permission. No distributed coordinator, provider-approved probe policy, production watchdog default, long-run SLA, independent E2 or released v0.18.
