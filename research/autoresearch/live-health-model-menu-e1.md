# #1618: trusted live service availability to model-visible tool disclosure (E1 opt-in)

This change **does not** implement a second availability monitor. It integrates the existing `AccessHealthMonitor`, principal-scoped retrieval and `RegistryExecutor` cooldown with the existing two read-only Open-Meteo `ToolSpec` source contracts.

## Original gap

The historical `evaluate_one` real Qwen/Open-Meteo E1 creates a new router per language/arm; it never registers or starts health probes. Its `state_ready` menu checks only source-observed *parameter readiness*, not *network liveness*. The original `OpenMeteoBoundInvoker` raises raw HTTP exceptions, while the product's executor marks passive cooldown only on trusted `InvocationUnavailableError`. Therefore the original connect_timeout does **not** falsify core watchdog correctness. Original E1 `all_visible`, `state_ready` results, original strict final JSON scoring and publicly disclosed source/gold are unchanged.

## Opt-in bridge — no live model inference claim

- `scripts/research_live_health_model_menu_e1.py` calls the exact existing `build_live_router`, preserves both native schemas and binds only a new *wrapper* of each original read-only invoker. The wrapper emits a controlled `InvocationUnavailableError` **only** on actual transport timeout/network/remote protocol error or HTTP 429 / 5xx. It neither retries a mutation nor converts invalid JSON, 401, 404, deterministic 4xx or model semantic errors into infrastructure health failures.
- A host must explicitly provide `trusted_health_probes` keyed by the two exact original routes. No random resource fetch, implicit HEAD, weather request, arbitrary endpoint probe, inferred health URL or model-written health status is generated. No probe is assumed healthy before it runs; call `check_health_once()` or start the existing `start_health_monitor()`. An absent probe remains UNKNOWN, excluded under **this opt-in strict E1 menu policy**. `healthy` must have a recent timestamp (default age at most 60 seconds). This is a research presentation policy, not a change to production fallback.
- Host then calls `capture_health_scoped_model_menu` with the current real `PrincipalContext`, original query, already validated host request inputs and optional source-projected prior observation. The canonical `capture_authorized_agent_tool_surface` filters policy, currently unavailable access paths and contract identity; `source_ready_visible_routes` enforces required native parameters. The added health gate uses current probe state and exact `RegistryExecutor` contract/cooldown state; only the intersected routes become the **actual tool-definition JSON** sent to a model.
- `HealthScopedModelMenu.assert_current()` is required **immediately before and after model generation**. `execute_health_scoped_host_call(menu, ...)` enforces the final gate immediately before calling the already existing `execute_scoped_host_call` and `RegistryExecutor`; a previously displayed or model-emitted route is never sufficient. The receipt rejects source/policy/health drift, probe expiry, replacement and cooldown changes. A concurrent health update between independent checks is not a single atomic full request transaction: the existing planner and executor also perform final source/availability validation.
- `temporary_unavailable` with zero definitions means input-ready routes have no recent healthy probe or are in cooldown; it does **not** mean semantic unsupported/no-fit. `inputs_missing` is distinct. A precompiled fallback still must be independently authorized, schema-compatible and read-only. The isolated trial does **not** invent a fallback.
- The handler intentionally does not swallow exception details for trusted debugging, but emits only controlled public error messages and must use existing sanitized `execute_scoped_host_call` for any model action.

## Tested and not yet measured

An Ubuntu Linux job uses `httpx.MockTransport`, the **real existing router, planner, RegistryExecutor, authorized model tool serializer**, simulated GET failures and host-scoped real invocations (no external network). It tests UNKNOWN, unhealthy, actual model-visible filtering, transport cooldown and next-call exclusion, separate geocode/weather route health, 429/5xx vs deterministic 4xx, explicit successful-probe recovery, bounded continuous background monitor, stale model snapshot/policy/schema changes. Only failure classification, native health state and selected tool-schema names are in the assertions: no model text or provider payload is exported.

**This first PR is an E1 deterministic integration seam, not a claimed actual independent healthy-provider E2 or new Qwen success.** Before promoting, a separate integration runner must provide legitimately host-owned low-cost service health probes (Open-Meteo provides no declared standard read-only health endpoint in this study), use a single long-lived process/router across adjacent live-provider Qwen tasks, classify real response failure and recovery, report probe attempts/candidate counts/latency/actual provider success, and retain the original published raw benchmark as immutable.

Never automatically treat HTTP 200 from an arbitrary business search as a trusted health probe; a cached or unauthorized endpoint cannot validate provider execution or permissions. The earlier wrong JA tool execution and incorrect final JSON are **not** transport outages and cannot be fixed by health filtering alone.
