# ServiceNow source-native external submission: strict read-only intake (E0)

**2026-10-20. Owner: #1346; dependencies #1477, #1291.**

The pinned `Xerrion/servicenow-platform-mcp` public, read-only,
12-tool MCP snapshot and 24 developer-authored visible DEV queries
are already in the repository's native external validation workstream.
They have produced **contradictory performance signals** across providers:
ServiceNow native lexical K5 17/20 versus E5 15/20 while Open-Meteo

generalized from a publicly seen single-domain evaluation. All known
unsupported DEV cases still return nonempty shortlists.

## What is implemented

`scripts/inspect_servicenow_external_submission.py` accepts a
**verbatim, out-of-repository JSON submission** and its **independently
supplied original UTF-8 byte SHA-256**, along with the *original pinned*
ServiceNow development manifest and the actual source-native captured
readonly MCP tool snapshot. It first runs the existing
`external_validation_servicenow_platform_mcp.validate_package`
against the exact independently pinned source revision and canonical
tool-schema hash. It then requires the submission to declare the
**same tool-source** identity and sha, without any substitute schema,
new endpoint, or inferred hidden operation.

Intake is read-only and **never runs a ranker or scorer**. It checks:

- Strict UTF-8 original bytes, bounded file size, SHA-256 match,
  duplicate JSON object keys including nested objects, BOM and
  nonfinite numeric rejection.
- Case IDs disjoint from visible DEV; bounded per-case Unicode query
  size; conservative exact/normalized-token containment and
  high-token-overlap checks against the frozen DEV cases and other
  submitted tasks (not a semantic originality certification).
- Source-owned exact tool names, original MCP top-level
  `inputSchema.properties` parameter names and duplicate gold
  rejection; supported/unsupported/forbidden strata, without
  inferring permission from any route or claiming that an LLM's
  semantic label is author-validated.
- EN/KO/JA × supported/unsupported coverage *reported*, with
  missing strata explicitly shown instead of filling them with
  fabricated translations.
- External author **claim** and request for review only, explicitly
  `verified_by_schemarouter:false`. **No JSON field can certify
  actual independent authorship or provider approval**.

The output never echoes user queries, expected tool IDs, case IDs,
reviewer/author identity, credentials, raw source or gold. It publishes
only original submission digest, pinned source digests, case-count and
language/stratum counts and a categorical `BLOCKED_EXTERNAL_REVIEW_UNSCORED`.
Even if every structural check passes, the result still states
`independent_e2_qualified:false`,
`heldout_scoring_allowed:false`,
`author_identity_verified:false`,
`calibrated_no_fit:false`,
`provider_native_tool_execution_measured:false`.

### Submission schema, structural checklist only

Top-level keys:
`schema_version:1`, `split:"proposed_external_unscored"`,
`source:{repository,revision,package,tools_sha256}`,
`author_claim:{authorship_type:"external_publisher_claimed",
 review_requested:true,organization:"...",verified_by_schemarouter:false}`,
and `cases:[...]`. Each case has a unique `sn-ext-` ID,
`language:"en"|"ko"|"ja"`,
`label:"supported"|"unsupported"|"forbidden"`,
`query`, `required_tools` and `required_fields`.
Supported cases have existing tool IDs; unsupported cases use
`[]`/`{}`. A forbidden case is **not** a permission proof even if
an upstream native route is known; provider-role authorization needs
a separate out-of-band review.

The native captured 12-tool JSON is currently generated by the
**existing pinned ServiceNow capture workflow** and should be supplied
as a separate review artifact; it is not magically available at a
guessed path under this repo. The submitter must retain the original
bytes in an access-controlled location and obtain permission before
any sensitive original requests, names or task labels are shared.

Example operator call (only when real source-author submission exists):

```bash
python -m scripts.inspect_servicenow_external_submission \
  --package-dir benchmarks/external-validation-servicenow-platform-mcp-dev-v1 \
  --snapshot /private/pinned-servicenow-readonly-tools.json \
  --submission /private/source-owner-cases-original.json \
  --declared-sha256 <precommitted-original-file-sha256> \
  --out /private/servicenow-unscored-intake.json
```

Do not commit the submission, its queries, or unreviewed author
credentials to GitHub. The supplied digest must have been fixed
*before* looking at candidate errors, and remains a review witness,
not an authorship signature.
