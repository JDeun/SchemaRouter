# Original A5 direct ToolCall — heterogeneous native source matrix (E1, opt-in)

## Intent

Draft #1760 connects one source-attested A5 P2 direct choice to the existing
registered native executor. The preexisting public Crossref / COD OPTIMADE /
DeepWiki MCP harness uses host-picked `ExecutionPlan` calls instead, and
three real adapter compilers already coexist in one G5 catalog without A5.
Close the **missing A5 multi-provider wiring**: several independently
host-approved, directly runnable original-paper tasks, each with one real
agent-selected ToolCall, all through the same native registry and G5 source.

## Approaches

1. **Chosen — opt-in matrix over existing A5 E1 bridge:** prevalidate a
   bounded immutable host scenario manifest, share one principal-scoped view
   and original G5 index, run one direct P2→agent→native call per scenario.
   Keep host-only receipts and enforce a pre-agreed route for each scenario.
2. Hard-code REST/OPTIMADE/MCP invocation in a research script: recreates
   routing and argument authority already implemented, brittle with adapters.
3. Promote an autonomous multi-provider agent/default product path: unwarranted
   while E2 and publisher permission gold are unavailable.

## Scope and guardrails

- Each scenario declares a unique ID, original native `tool.endpoint` route,
  owner-declared intent/concept, trusted host input and a model/agent pair.
  All cases must be validated **before any model generation or remote I/O**.
  The declared case route must belong to the principal-visible tool surface
  and be an actual registered, read-only and non-destructive endpoint.
- Distinct registered native source protocols share the one registry,
  principal and source graph. Do not create a second executor, reconstruct
  field semantics from model prose, auto-grant MCP `readOnlyHint`, infer
  credentials or bypass host-reviewed source/license and authorization.
- An already approved **scenario route** is narrower than any other
  model-selected P2-compatible source: constrain direct dispatch to that
  exact route **before** agent generation, even when an unrequested
  input-free tool could independently answer the same concept. Preflight
  pins every scenario's registered native invoker and binding generation
  **before** invoking any P2 availability callback, not only those of the
  currently executing case.
- All successful calls use the existing
  `run_paper_scoped_native_direct_e1` and `SchemaRouter.execute` once per
  case, preserving per-call binding generation and host materialization.
  The host may inspect typed receipts but none become model observations.
- If a case abstains, requires arguments or fails, no success is reported
  for that case or for the whole matrix; later cases are not executed.
  Earlier completed read-only calls cannot be rolled back; document this.
- The API supports 1–5 cases. A successful **single-provider** call is not
  evidence of heterogeneous coverage: report registered source types and
  a derived heterogeneity flag from the executed manifest.
- Model route/name and arguments remain *untrusted*. Approved scalar roots
  only. Source-specific HTTP/MCP result authenticity, external permissions,
  real-model route selection quality and publication rights are separate.
- Current P2 FieldGroup proof accepts **scalar output contracts only**. Real
  Crossref's `message` object and OPTIMADE `elements` array cannot be
  declared field-complete by this bridge; do not cast them to strings or
  weaken typed checks. Integration proves adapter/protocol wiring with
  genuinely source-compiled scalar fields, not a fabricated E2 score.

## Verification

1. Build one registered native router from real OpenAPI, MCP, and OPTIMADE
   **adapter compilers** with host-attested scalar semantics and native
   bound invokers. Three separate understood P2 intents must execute through
   the one scoped matrix; wrong agent argument IDs never reach invokers.
2. Fail closed for duplicate cases/route, hidden or non-read-only route,
   missing/unreviewed host arguments, and a manifest with an invalid *later*
   case (zero calls even for the otherwise valid first case).
3. Provider error or mid-execution source/binding drift gives no success
   matrix; no raw private observations are serialized into public results.
4. Try explicitly authorized keyless native provider live probes separately;
   label any host-scripted or simulated component as E1, never E2.

## Release and research boundary

independent model/tool-choice E2 qualification. Publisher-authored gates
