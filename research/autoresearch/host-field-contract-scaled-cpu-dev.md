# #1447 follow-up — Production selector scalability on mixed adapter catalogs (DEV)

## Hypothesis and limits

The [merged product API #1447](https://github.com/JDeun/SchemaRouter/pull/1447) now safely requires **explicit host-supplied** read-only `HostFieldContract`, a trusted `PrincipalContext`, and a complete current authorized `CapabilityRetrieval` before claiming a single exact output or enum conjunction match. This prevents a truncated Top-K accidentally declaring uniqueness. The cost of materializing *all* typed candidate schemas at 100–500 routes is unknown and could erase search performance gains. Performance needs actual product profiling, not merely source counts.

We **reuse the existing registered** `benchmarks/current_adapter_scaled_authorized_dev_v1.py` fixture at exactly **100, 250, 500** routes, all parsed through current OpenAPI/MCP adapters and native database/vector/graph `ToolSpec`. Five mutation routes denied to synthetic Viewer; viewer-visible benchmark output `audit_tag` is projected away. No simulator replaces the public selector, and the calls go through the real current `SchemaRouter.retrieve_authorized` path. The local fixtures are author-created, not live provider-supplied. Query labels and structured required fields are **also author supplied**, not a real EN/KO/JA intent extractor.

## Preregistered CPU measurement

- Six fixed case categories × EN/KO/JA, **five repeats each size** = **90 samples per size, 270 same-author paired samples**. Cases: unambiguous read invoice total+ID, vector title+distance; denied viewer payment ID; out-of-schema field; hidden `audit_tag`; and generic `payload` (ambiguous among many registered read-only routes).
- For every case, time a separate **normal complete authorized retrieval** (`k=catalog size`) and the **whole `select_authorized_field_contract` public call** (which independently retrieves the authorized catalog, deep-validates envelope and checks declared fields). Both run on the same read-only synthetic fixture, subject to order/cache/machine noise. Report raw per-case timings, p50/p95/p99 nearest-rank (nonparametric), max/mean, CPU peak RSS, source SHA-256, checkout revision and full receipt. This is not a paired causal latency decomposition: separate sequential runs may be affected by caches.
- Validate exact `size-5` allowed identities, missing five denied mutators, absence of `audit_tag` in every viewer-visible synthetic route, route-specific source fields and full catalog `total_ranked`, and **no unsupported/ambiguous/denied decision is selected**. The unique source cases must select only their expected visible route. No execution or remote model.
- Add negative test at each 100/250/500 size proving small `k=5` cannot be silently treated as full catalog even if an apparently correct route appears in the first five. The public product API must **abstain**.
- The test is a dedicated read-only Ubuntu24.04 GitHub Actions CPU, 30-minute timeout, 90-day immutable artifact. Full protected CI, CodeQL and baseline validation still required before merging research-only code.

## Interpretation

- **GO for research artifact only** if all source-locked 270 comparisons complete and authorization/field invariants hold without flaky/racy data. Produce real timings before describing performance.
- **No universal latency SLO** is set from this single GitHub Actions runner or synthetic fixture; p99 over 90 observations per catalog is descriptive and not tail-latency certification. No cold-start/warm-start population-level SLO, genuine authenticated principals, provider-disjoint catalogs or downstream agent success is tested.
- The host contract selector is already merged in an **opt-in read-only** form. Even if measured slow at 500, don't weaken the complete-authorized-surface requirement to produce flattering p95 numbers. Later safe optimization might use a principal-projected contract index or prove completeness with an independent registry-version-bound authorization snapshot, but it must first demonstrate zero hidden-field leakage and exhaustive equivalence.
