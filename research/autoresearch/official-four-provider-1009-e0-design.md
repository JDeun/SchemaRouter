# B1 E0 — one genuine four-provider 1,009-operation native catalog

## Intent and evidence boundary

Verify that the *same* native registry and source-owned posting/graph journal
can index **1,009 original publisher operations in one versioned catalog**,
without manufacturing executable endpoints, provider semantics or gold.
This extends the separately proven original OpenAI 355-operation and GitHub
651-GET catalogs, with Ollama 2 GETs and Pirate Weather 1 GET.

This is original *publisher schema* evidence, **E0 only**; it does not meet
independently authored source-authorized 500/5,000 heterogeneous B1/E2,
model utility, the A6/A7/A10 gates, #1346 or #1477. #1356 stays HARD HOLD;
the stacked #1755 remains Draft/unmerged.

## Decisions and alternatives

- **Chosen:** compile the existing byte-pinned authentic OpenAI document into
  one publisher `ToolSpec` of 355 supported HTTP endpoints, use the existing
  pinned GitHub 651-GET publisher bundle, and register the two independently
  pinned smaller providers. One mixed registry; the standard original
  native posting/graph index, authorization policy and journal only.
- **Rejected:** add the prior 358- and 654-route receipts arithmetically.
  They represent separate catalogs, and cannot establish one 1,009-route
  registry, shared fingerprint/route namespace or mixed-version churn.
- **Rejected:** split GitHub and OpenAI into thousands of fake providers or
  weaken the existing OpenAPI converter to include seven literal-query or
  nine unsupported non-JSON OpenAI operations. Preserve exact original
  operation paths/verbs/IDs and the same completeness guard.

## Observable acceptance

1. Parse only the exact original publisher fixtures and original notices
   through the existing SHA-256/length/Git-blob pins. Source inventories
   remain GitHub 823 paths/651 native GETs; OpenAI 371 HTTP operations,
   including 355 natively represented and explicitly excluded 16.
2. Register exactly four real publisher `ToolSpec`s, with **1,009 unique
   source route keys** and no granted authority. Original methods, route
   paths, required path inputs, declared authentication and mandatory JSON
   request-body constraints survive OpenAI conversion. Exclude unsupported
   literal query paths and non-JSON-only request bodies.
3. Verify at each registry version the actual source-owned journal against
   both a fresh full index/graph build and an **independently derived
   original-source `(provider-key, operationId)` route manifest**. Churn
   authentic whole providers in both directions:
   **1,009 → 358 → 1,009 → 654 → 1,009**. Reject stale native lookups before
   replay; reject a deliberately forged no-op journal replay.
4. Every stage must remain default-deny, with zero source-unreviewed semantic
   postings, inferred graph edges, provider calls and execution grants.
5. Measure indexed build/journal refresh wall time and CPU process max RSS
   as **observed E0 diagnostics**, not SLAs; do not equate an empty semantic
   index with representative production retrieval latency.
6. Offline tests, repo Ruff, changed-module static typecheck and dedicated
   Python 3.12 CI cover the new real mixed-catalog audit. Maintain the
   canonical paper implementation handoff and its external blockers.

## Explicit non-goals

No API calls, credentials, inferred source permission/license grant,
semantic embeddings, new execution engine, cross-provider typed joins,
independent EN/KO/JA model test, synthetic expansion to 5,000 authentic
routes, default-routing change or release.
