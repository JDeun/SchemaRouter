## 2. New actionable correction from the research (not another model trial)

**Root-cause candidate A: validated dependency topology, not just LLM size.**
Previous E0 accepted the correct first provider call and asked an LLM to infer what to do next. Before adjusting prompts, evaluate an *execution-attested* typed dependency graph: registered output field identity, semantic type, unit/enum and schema → authorized required downstream input, checked with a safe real source or approved immutable fixture. Each edge records original provider, source revision and successful provider invocation evidence. At runtime the graph **never grants authority** and is filtered again by current principal policy. End-to-end correctness still demands model/user task intent and verified final oracle, not a hard-coded path/gold from researcher-authored tasks.

**Root-cause candidate B: language-specific value normalization.** Separate `correct tool` from `correct parameter value`, including Korean/Japanese surface strings vs source-author canonical IDs, units and enums. Provider schemas and source-normalized values remain authoritative; do not invent transliterations.

**Root-cause candidate C: wrong abstention semantics.** An unregistered operation, a present-but-unauthorized operation, a missing required parameter, ambiguity among allowed tools and a completed request have different *internal* states; externally denied and absent must remain **indistinguishable** to a principal who cannot see the route. Adopt ACEBench/FunctionChat-Bench AST and special-case methodology, not public self-generated labels.

**Root-cause candidate D: untrusted observation injection.** Intermediate tool response is data, not an instruction to invoke extra tools or reveal hidden capabilities. The host must validate and project *before* model replay, and reauthorize *again* at each physical call. Model-facing telemetry never returns private source-existence bits.

## 3. Revised priority / stop rules for #1510

1. **Read and map upstream** Qwen3/Qwen-Agent protocol, MCP schema and existing PydanticAI/Agents SDK integration before any code or larger-model exploration. Check Qwen no-thinking and stop-token behavior against upstream guidance, without claiming current protocol parser is the only observed failure.
2. **Design (not deploy) KOPA-style execution-attested dependency graph** for A02/R03, with cardinality, typed field mapping, per-edge provenance and fresh source authorization; explicitly research availability/licensing of KOPA source artifacts first.
3. **Reuse public native-language evaluation methodology:** FunctionChat-Bench KO, Nejumi/BFCL JA, MASSIVE-Agents multilingual, ACEBench ambiguous/missing/no-call, while keeping public datasets separate from locked publisher-authored E2. Compare grades under local deterministic AST/state/policy or independently reviewed rubrics, not paid GPT-only grading.
4. **Use AgentDojo + MCP specification as an S01/S02 hard boundary**. Threat test provider-result prompt injection, malicious tool descriptions/annotations and policy mutation without leaking hidden source metadata.
5. Obtain disjoint **EN/KO/JA original provider** E2 task creators, approved original tool catalogs and complete live / preserved source oracles. Only **then** compare pinned small free model candidates under the same fixed K, token/CPU budgets, latency, confidence intervals and false refusal rates.

**Stop** ad-hoc exposed synthetic prompt/threshold/model tuning for production. The original 0.6B 0/3 and 1.7B 2/3 three-case DEV remain development observations, **not** model-promotion proof. Any benchmark copied from a public upstream repo is public/visible and **not an independent SchemaRouter E2** unless separately sourced and correctly isolated.
