# SchemaRouter 0.12.0

SchemaRouter 0.12.0은 현재 pre-1.0 architecture의 **stable-core product closure release**입니다.

0.11.0이 first-class bounded typed capability retrieval을 확립했다면 0.12.0은 architecture/API boundary를 freeze하고 installed-package/adapter policy regression coverage를 강화하며 research가 독립적으로 계속되는 동안 released artifact 자체를 canonical stable baseline으로 만들어 product cycle을 닫습니다.

## Stable-core boundary

Product architecture는 다음 contract를 중심으로 명시적으로 freeze됩니다.

```text
Python / OpenAPI / MCP / OPTIMADE / adapter plugins
                         |
                 typed registry
                         |
          bounded capability retrieval
                         |
            agent / application
                         |
              planning/calls
                         |
       validation + local execution policy
                         |
                bound execution
```

Research는 이 boundary 뒤에서 ranking/index implementation, shortlist default, adaptive depth, corrective re-retrieval을 개선할 수 있습니다. Benchmark improvement 자체는 public facade를 redesign할 충분한 이유가 아닙니다.

## Public retrieval facade

현재 research cycle은 다음을 보존해야 합니다.

- `SchemaRouter.retrieve(..., k=5)`
- `SchemaRouter.aretrieve(..., k=5)`
- `SchemaRouter.retrieve_executable(..., k=5)`
- `SchemaRouter.aretrieve_executable(..., k=5)`
- 동등한 `ConfiguredSchemaRouter` surface

`CapabilityCandidate`는 full effective input/output JSON Schema, declared parameter/output field, semantic ID, optional unit/dimension/qualifier, policy metadata, fingerprint를 포함한 registered executable contract를 계속 보존합니다.

Retrieval은 side-effect free이며 execution authority를 부여하지 않습니다.

## Stronger closure validation

0.12.0은 release artifact 자체가 frozen contract를 exercise하도록 product validation surface를 확장합니다.

Installed wheel/sdist consumer acceptance 검증:

- sync/async bounded retrieval
- executable-ready retrieval
- retrieval이 tool side effect를 만들지 않음
- full input/output schema 유지
- registered tool/endpoint fingerprint 유지
- actual invocation은 별도 operation

Framework integration regression test는 LangChain/LlamaIndex wrapper가 SchemaRouter local mutation/execution policy를 우회할 수 없음도 검증합니다.

## Research remains separate

Product closure 이후에도 active research는 계속됩니다.

- stronger-agent B2 replication
- 대규모 독립 홀드아웃을 이용한 에이전트 작업 효용성 일반화 검증
- 최종 답변의 사실·값·단위·출처 품질
- adaptive shortlist depth
- execution-state-aware corrective re-retrieval
- representation/index studies

결과는 compatible internal/default를 개선할 수 있지만 reproducible correctness/security/policy/execution-authority/API-integrity/packaging defect가 없는 한 product architecture를 다시 열지 않습니다.

## Compatibility

0.12.0은 0.11.0 대비 breaking public API change를 도입하지 않습니다.

Existing planning, invocation, validation, policy, async, batch, streaming, tracing, persistence, inspection, optional integration surface는 유지됩니다.

SchemaRouter는 **Beta / pre-1.0**입니다. Stable-core freeze는 architecture가 더 이상 active research variable이 아니라는 뜻이며 future 1.0의 long-term semantic-versioning commitment와 동일하지 않습니다.

## Release integrity

Automated release pipeline은 exact release-prep commit이 protected CI를 통과하도록 요구한 뒤:

- exact green `main` SHA에 annotated `v0.12.0` tag 생성
- resolved release SHA에서 wheel/sdist build
- 두 artifact clean-install/smoke-test
- provenance attestation과 SPDX JSON SBOM 생성
- OIDC로 PyPI publish
- GitHub Release asset publish
- public PyPI wheel/sdist를 내려받아 trusted build와 digest 비교
- checkout 밖에서 exact public release를 wheel, sdist, lightweight extras, combined integration extras로 재설치

Post-publish check가 모두 green일 때 product track이 완전히 closed된 것으로 간주합니다.
