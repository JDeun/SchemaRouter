# SchemaRouter 0.18.0

SchemaRouter 0.18.0은 **명시적인 no-match 실행 권한 경계, 선언된 다국어 기능 메타데이터, 선택형 결정 백엔드 검증, 재현 가능한 외부 소스 검증**에 집중합니다. Python 패키지의 역할은 타입 기반 기능 검색과 권한이 관리되는 실행이며, 범용 에이전트 오케스트레이터나 자동 번역기가 아닙니다.

## 라우팅 및 no-match 제어

- 새로운 명시적·선택형 principal-bound 실행 게이트(`ainvoke_selective` 및 관련 계약)는 승인된 후보 목록의 적합성·권한·레지스트리 상태가 불충분할 때 **계획 생성이나 도구 호출 전에 거부**할 수 있습니다. 임계값은 호스트가 독립적으로 보정해 제공해야 하며, 기존 `retrieve()` 및 `ainvoke()`의 기본 동작이 자동으로 의미적 거부 분류기로 바뀌지는 않습니다.
- 인덱스 기반·전체 탐색 기반 어휘 검색 모두 **명시적으로 선언한 엔드포인트 operation alias**를 반영합니다. 기존 라틴 문자·한국어와 함께 일본어 문자를 토큰화해 선언된 일본어 필드 별칭을 찾을 수 있습니다. 미선언 기능을 만들어내거나 요청을 자동 번역하는 동작은 아닙니다.
- 후보의 출처·레지스트리 식별자·실행 권한·정책 바인딩을 실제 실행 전에 재검증합니다. Top-K 후보가 비어 있지 않다고 해서 요청이 지원되거나 실행 가능하다는 뜻은 아닙니다.

## 선택형 결정 백엔드 연동

- 호스트가 설정하는 Microsoft Foundry Decision-1 HTTP 어댑터를 **선택적 후보**로 제공합니다. HTTPS origin, 명시적 자격 증명·배포 이름, 유한 선택지, 허용된 선택지 ID, `none_of_above` 거부 응답을 검증합니다. 잘못된 자격 증명·페이로드·확률·사용량·과도한 응답은 거부합니다. 이는 어댑터/형식 계약 검증이며 **Microsoft 실서비스 모델의 독립 품질 검증**이 아닙니다.
- Laya와 System One 응답의 잘못된 Boolean·숫자 선택지 ID 변환, 신뢰도 및 확률 불일치, 선택지 이외 응답을 엄격히 거부합니다.
- Jev 네이티브 결과·외부 프로토콜 검증기가 잘못되거나 출처가 확인되지 않은 활성화 데이터를 거부합니다. 유료 Jev나 실제 Laya 모델 벤치마크를 실행했다는 의미는 아닙니다.

## 외부 개발 검증의 범위

ClicShopping·ServiceNow·SmartMCP의 **개발 단계 전용** 소스·벤치마크 무결성 검증을 보강했습니다. Clear Your Tools의 SDK/loopback 검사와 HYSET 공개 입력 사전 검사도 각각 범위가 제한된 근거입니다. 이 결과는 독립 작성된 프로젝트 간 홀드아웃 검증이나 실제 운영 환경의 권한 검증이 아닙니다.

- ClicShopping의 동일 Git SHA는 공개 포크에서 확인됐습니다. 검증된 32+10개의 **공개 DEV** 사례에서 미지원 요청에도 비어 있지 않은 후보가 나오는 한계가 남았습니다.
- ServiceNow의 `readonly` 도구 12개를 사용한 공개 DEV에서 필수 도구 재현율은 전체 공개 **100%**, SchemaRouter K3 **75%**, K5 **85%**였습니다. 독립 확인 결과로 간주하지 않습니다.
- HYSET 원 논문의 `best.pt`는 공개되지 않아 입력 사전 검증만으로 재현을 주장할 수 없습니다. CYT 전체 에이전트와 pi-jev/로컬 Laya 네이티브 비교도 아직 확인되지 않았습니다.
- 릴리스 전 외부 증거 목록에서 로컬 DEV/스모크 통과와 외부 승인, 독립 정답 검수, 실제 모델 평가 및 홀드아웃 근거의 미확보 상태를 분리합니다.

## 연구 무결성과 지표

동결된 0.14 실험의 **사전 등록 제품 품질 가설은 부정적 결과**를 유지합니다. #432 대규모 홀드아웃에서 전체 도구 공개보다 모든 배포 가능한 축소 후보의 작업 완료율이 낮았으며, #424의 최종 사실 답변 품질 게이트도 실패했습니다. #506 출력 필드 투영은 문맥을 줄였지만 근거 없는 사실 비율의 비열등성 게이트를 통과하지 못했습니다. 과거 실험의 행·임계값·결과는 변경하지 않았습니다.

후속 테스트에서는 **도구 실행 과제 완료**와 **근거가 충분한 최종 답변 성공**을 분리합니다. 실제 `0.17.0` wheel과 릴리스 후보 wheel을 설치해 선언된 다국어 별칭과 미지원 요청을 확인하는 결정적 회귀 검사는 독립적인 다국어 에이전트 작업 성능 검증이 아닙니다. 배포된 wheel을 사용한 새로운 독립 검증은 배포 이후 #1344에서 다룹니다.

## 호환성·보안·마이그레이션

- 기존 결정적 라우팅, principal/권한 검증 및 일반 공개 진입점은 기본 동작으로 유지합니다.
- 새로운 no-match 실행 정책은 검증된 출처·레지스트리·principal과 독립적으로 정당화된 임계값이 있을 때만 선택적으로 사용합니다. 기본 보정이나 자동 제공자/모델 선택은 지원하지 않습니다.
- 선택형 Microsoft Foundry 연동에는 명시적인 HTTPS 엔드포인트·배포·자격 증명 설정이 필요하며 이용 요금이 발생할 수 있습니다. 결정 백엔드는 도구 실행 권한을 부여하지 않습니다.
- 잘못된 응답과 출처를 더 엄격하게 검증해 이전에 암묵 변환으로 수용되던 값이 거부될 수 있습니다. 호출자는 선언된 타입에 맞는 값을 전달해야 합니다.
- 배포 출처 및 실제 설치 wheel 검증은 [릴리스 체크리스트](../release-checklist.md)와 [버전 정책](../versioning.md)을 따릅니다. GitHub Release 및 PyPI의 SHA는 릴리스 매니페스트에서 확정되며, 여기서 미리 단정하지 않습니다.
