# SchemaRouter 0.15.0

SchemaRouter 0.15.0은 0.12에서 확립한 안정 실행 경계와 0.14의 운영 기능 위에 **provider 중심 등록과 capability runtime**을 확장한 릴리스입니다.

SchemaRouter의 역할은 계속 타입 기반 capability 검색과 스키마 인식 실행에 한정됩니다. 자율 오케스트레이션을 추가하지 않았고, 진행 중인 연구 결과를 안정 제품 보장으로 승격하지도 않았습니다.

## Provider 중심 등록

이제 사용자는 provider가 제공하는 모든 프로토콜이나 SDK를 먼저 알지 않아도 provider identity에서 등록을 시작할 수 있습니다.

```python
from schemarouter import SchemaRouter

router = SchemaRouter()
resolution = router.resolve_provider("materials-project")
registration = await router.add_provider("materials-project")
```

내장 acceptance profile은 Materials Project, Crossref, Tavily, APIs.guru, OData.org V4 reference service를 포함합니다. Provider profile은 기존 adapter 위의 얇은 onboarding 계층입니다.

URL 기반 method는 기존 OpenAPI, OPTIMADE, GraphQL, OData, OpenRPC, MCP ingestion 경로로 전달됩니다. 선언형 HTTP/JSON은 명시적으로 신뢰된 `ToolSpec`을 사용합니다. Python SDK와 caller-owned transport는 계속 명시적인 trusted binding이 필요하며, 패키지가 설치되어 있다는 이유만으로 실행 권한을 부여하지 않습니다.

릴리스 게이트 호환성 근거에는 provider profile을 거치는 로컬 GraphQL, OpenRPC, MCP reference implementation도 포함됩니다. Public provider 검사는 특정 시점의 호환성 근거이지 영구적인 uptime 보장은 아닙니다.

## State-aware corrective retrieval

0.15.0은 `reretrieve_state_aware()`와 `areretrieve_state_aware()`를 통한 명시적 state-conditioned corrective retrieval을 추가합니다.

이 API는 현재 상태에서 부적격인 후보를 제거하고 남은 eligible capability에서 backfill할 수 있습니다. 기존 `retrieve(..., k=5)` / `aretrieve(..., k=5)` facade는 변경하지 않으며 additive·opt-in입니다.

## Capability dependency graph와 drift 처리

Capability graph 구성은 indexed 및 incremental 유지가 가능한 구조로 확장됐습니다. Indexed dependency construction, deterministic SCC 분석과 bounded cycle witness, incremental rebuild, atomic compare-and-swap snapshot publication, 검증된 full-rebuild fallback, publication failure 시 source/predecessor 보존이 포함됩니다.

Sparse graph benchmark는 1k, 10k, 50k capability 규모를 다룹니다.

## Portable artifact, snapshot, decision trace

Capability graph artifact와 snapshot에 명시적인 format version과 deterministic migration 동작을 추가했습니다. Legacy 1.0 graph artifact는 기존 edge를 external evidence로 보존한 채 1.1로 migration됩니다. 기존 pre-envelope snapshot도 검증 후 읽고 versioned envelope로 migration할 수 있습니다.

또한 privacy-safe capability decision trace, `router.inspect(...)`, CLI inspection, HTML dashboard integration을 추가했습니다.

## Live acceptance에서 발견한 호환성 수정

확장된 Materials Project provider-first smoke에서 OPTIMADE streamed compressed-response 재구성 결함이 발견됐고, 0.15.0에서 이를 수정하고 regression coverage를 추가했습니다.

## 호환성과 stable-core 경계

안정 retrieval/execution facade에 의도적인 breaking change는 없습니다. `retrieve(request, *, k=5)` / `aretrieve(request, *, k=5)` 시그니처는 유지되고, state-aware re-retrieval은 additive이며, provider-first registration은 기존 adapter/execution contract를 재사용합니다. Credential, live client, SDK object, transport handle은 persisted/model-visible schema 밖에 유지됩니다.

SchemaRouter는 계속 **Beta / pre-1.0**입니다.

## 연구 경계

현재 routing 연구는 package release와 독립적으로 계속됩니다. Large held-out semantic benchmark, final-answer quality 평가, 남은 projection/decision-backend confirmation은 제품 correctness, security, packaging, API 결함을 드러내지 않는 한 0.15.0 배포의 blocker가 아닙니다.

따라서 진행 중인 partial research row를 이번 릴리스의 제품 보장으로 제시하지 않습니다.

## 릴리스 무결성

배포는 정확한 0.15.0 release commit이 protected CI/security matrix와 release-gated pinned protocol compatibility reference를 통과해야 진행됩니다. 이후 자동 workflow가 `v0.15.0` tag 생성, wheel/sdist clean-install 검증, SPDX SBOM 및 provenance attestation 생성, `SHA256SUMS.txt`와 `release-manifest.json` 생성, PyPI Trusted Publishing, 공개 artifact digest 검증, published artifact와 integration extra 재설치를 수행합니다.
