# 네이티브 인덱스 FieldGroup → 고정 K 에이전트 브리지(E0) 구현 계획

> **에이전트 작업자 안내:** 실패 테스트를 먼저 작성하는 RED/GREEN TDD를 따르고, 기존 에이전트 실험 조건을 보존하며, 리뷰 전에 전체 테스트를 확인합니다.

**배경:** 이슈 #1560, #1477 및 누적 개발 기반 PR #1753(`59ae023`). 승인된 원 논문 구현 방향은 원본 소스가 선언한 개념 → 완전한 타입 기반 FieldGroup → 현재 요청자에게 공개 가능한 네이티브 경로 → 외부 에이전트입니다. 이 작업은 연구 전용 콜백이며, 제품 기본 검색이나 실행 권한을 부여하지 않습니다.

**검토한 접근 방식:** (1) 에이전트/평가기 재구현(중복 및 정답 유출 위험으로 제외), (2) 인덱스 기반 순위를 기본 라우터에 적용(E2 및 no-fit 검증이 차단되어 제외), **(3) 기존 posting 인덱스를 격리된 `EVAL-FIXED5-OPTIN` 선택기와 권한 검증된 모델 뷰에 연결(채택)**. 이 방식으로는 독립적으로 캡처한 권한 있는 모델 뷰에 없는 경로를 복구할 수 없습니다. 이 별도 소스 뷰 한계는 명시적으로 기록하고 안전하게 차단합니다.

**범위:**
- 기존 P1/P2 타입·출처·권한 증거 및 기본 `retrieve_authorized` 경로를 보존합니다. 명시적 opt-in 연구 선택기만 변경합니다.
- 직접 인덱스 후보에는 필수 입력 계약이 없어야 합니다. 생산자→소비자 경로 연결은 기존 G5 그래프 선택기에서만 처리합니다.
- 오래된 인덱스·정책·가용성, 숨겨진 필드, 불일치하는 fingerprint, 중복되거나 모델 뷰에 없는 경로, 안전하지 않은 백엔드 선택, 모델에 공개할 스키마의 바이트 예산 초과를 거부합니다. 선언되지 않은 개념은 보정된 no-fit이라고 주장하지 않고 판단을 보류합니다.
- 새 에이전트 루프, 과제 정답 접근, 합성 E2 성과 주장, 릴리스 또는 병합 승격은 포함하지 않습니다.

## 작업 1 — 원본 소스 안전성을 지키는 직접 인덱스 개념 선택

**파일:** `src/schemarouter/native_semantic_index.py`, `tests/test_native_semantic_index.py`

1. `lookup_concepts(..., input_free_only=True)`가 필수 타입 입력을 가진 원본 엔드포인트를 제외하되, 일반 질의-개념 조회는 변경되지 않음을 보여 주는 실패 테스트를 추가합니다.
2. 해당 테스트를 실행하여 예상한 실패를 확인합니다.
3. 명시적 입력 없는 경로 옵션을 이미 검증된 네이티브 `lookup` 필터에 전달합니다. 필터링 로직을 중복 구현하지 않습니다.
4. 대상 테스트와 기존 네이티브 인덱스 테스트를 다시 실행합니다.

## 작업 2 — 기존 평가기 어댑터

**파일:** `scripts/research_authorized_concept_fixed5_agent_bridge.py`, `tests/test_research_authorized_indexed_fixed5_bridge.py`

1. 완전한 직접 필드 집합, 지원하지 않는 바인딩 엔드포인트, 원본 소스/뷰 불일치, 정책·범위 변경, K 초과 시 보류, 제한된 검증된 순위화, 타입 기반 상태, 원래 실행기를 사용한 스크립트형 E0 `run_generated_episode` 테스트를 실패하는 상태로 추가합니다.
2. 어댑터가 없는 상태에서 예상한 실패를 확인합니다.
3. 기존 뷰 무결성과 원본 소스 fingerprint 검사를 재사용하는 `AuthorizedIndexedFieldFixed5Selector(view, catalog, index, research_ranker=...)`를 최소 범위로 구현합니다. 선택기에 전달하는 정보는 질의와 캡처된 공개 원본 소스 ID뿐입니다.
4. 기본 동작이 변경되지 않았고 분리된 권한 검증 후보 이름 이외에 새로운 모델/백엔드 접근이 없음을 확인합니다.

## 작업 3 — 재현성과 후속 인계

**파일:** 간결한 연구 구현 기록과 기존 계획서.

1. 관련 pytest, Ruff, Pyright 및 저장소 전체 pytest를 실행하고 *모든* 실패를 보고합니다.
2. 격리된 누적 Draft 브랜치에 커밋하고, 허가된 인증 수단이 있을 때만 게시합니다. 병합하지 않습니다.
3. 독립 원저자 #1346, 에이전트 비교 #1477의 E2, 보정된 no-fit 및 릴리스 #1356의 상태를 `E0_ONLY / BLOCKED_EXTERNAL`로 명시합니다.

**리뷰 중점:** 어휘 검색에서는 보이지 않던 경로가 모델 도구로 유출되는지, 필수 입력 엔드포인트가 직접 실행 가능한 것으로 표시되는지, 부분 권한 범위에서 숨긴 필드가 공개되는지, 선택과 공개 사이 요청자·정책·인덱스가 변경되는지, 정답 레이블이 유출되는지, 연구용 순위가 실행 권한이나 no-fit 판정 권한을 주장하는지 확인합니다.
