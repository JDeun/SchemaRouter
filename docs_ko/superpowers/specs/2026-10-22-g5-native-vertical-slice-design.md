# G5 원본 소스 기반 개념 그래프 → 고정 K 에이전트 과제 검증의 수직 통합

**상태:** 유지관리자가 방향을 승인했으며, 세부 설계 검토를 위한 문서

**작성일:** 2026-10-22

**주요 이슈:** [#1535](https://github.com/JDeun/SchemaRouter/issues/1535), [#1560](https://github.com/JDeun/SchemaRouter/issues/1560), [#1477](https://github.com/JDeun/SchemaRouter/issues/1477)

**보안 선행 조건:** [#1532](https://github.com/JDeun/SchemaRouter/issues/1532), [#1450](https://github.com/JDeun/SchemaRouter/issues/1450)

**다국어·외부 검증 선행 조건:** [#1339](https://github.com/JDeun/SchemaRouter/issues/1339), [#1346](https://github.com/JDeun/SchemaRouter/issues/1346)

## 1. 의도와 증거의 경계

다음 개발 단계는 검색·CPU·프롬프트의 작은 E0 최적화를 반복하는 대신, **실제 사용자가 이용할 수 있는 통합 기능 하나와 그 기능의 과제 단위 증거**를 제공해야 합니다. SchemaRouter는 외부 에이전트가 사용할 등록된 원본 도구와 타입이 명시된 필드를 발견하는 시스템이지, 에이전트 오케스트레이터나 LLM이 권한을 만들어 내는 시스템 또는 별도의 그래프 DB가 아닙니다.

기존 기본 동작과 릴리스 상태는 변경하지 않습니다. 동결된 #432 과제 실험에서 성공률은 SR-5 29.19%, FULL 49.62%, 진단용 ORACLE 70.98%였습니다. 합성 Top-K나 토큰 지표를 개선하더라도 이 결과를 뒤집어 해석할 수 없습니다. 실제 Open-Meteo 소스를 호출하는 EN/KO/JA 로컬 Qwen E1 사례에서도 엄격한 세 과제 가운데 0~1개만 완료된 경우가 잦았습니다. 공개된 이 사례를 독립 E2 홀드아웃으로 재사용할 수 없습니다. 출처 사용이 허가되고 작성자가 분리된 과제·정답 데이터는 #1346에서 여전히 차단되어 있습니다. v0.18 릴리스 PR #1356은 **HARD HOLD**입니다.

이번 통합에서의 사용자 성공은 명시적인 권한을 가진 요청자가 등록된 원본 소스와 호스트가 검토한 개념을 질의했을 때, 외부 에이전트에 **필요한 완전한 원본 경로·필드 계약만 제한된 수로 제공**하고 실제 작업 순서를 시도할 수 있는 것입니다. 실험에서는 최종 과제 성공 여부와 실패 단계를 구별해야 합니다. 부정적 결과도 유효한 결과이며 자동 미세조정을 정당화하지 않습니다.

## 2. 선택한 방법과 보류한 대안

**채택안:** 기존 API와 그래프 인덱스를 명시적 opt-in 선택 인터페이스로 구성하고, 실제 과제 중심의 대응 E1 실험을 수행합니다. 안정적인 기본 API를 바꾸지 않으면서 제품에 의미 있는 통합을 진행할 수 있습니다. 단, 독립 증거에 따른 승격과 상위 이슈 종료는 #1346을 통과하기 전까지 금지됩니다.

보류한 대안은 다음과 같습니다.

1. **그래프·CPU 미세 최적화를 먼저 완료:** 지역 처리량은 개선될 수 있으나 에이전트가 실제로 그래프를 활용한다는 근거가 없습니다. #1700에서는 통합 실측 병목이 발견되기 전까지 독립 최적화를 추가하지 않습니다.
2. **새 에이전트 실행기·그래프 DB·CodeGraph형 증거 시스템 구축:** 이미 존재하는 구성 요소와 중복되고 동결된 과제 실패를 직접 해결하지 않습니다. #1711은 비차단 M5 연구로 유지합니다.

## 3. 기존 구성 요소 재사용

| 책임 | 기존 모듈·인터페이스 | 적용 원칙 |
| --- | --- | --- |
| 검토된 개념 별칭과 결합형 필드 요구 | `concept_retrieval.py`: `NativeConceptCatalog`, `resolve_native_concepts`, `retrieve_authorized_concepts` | 원본·별칭 충돌 검사를 재사용하고 선언되지 않은 별칭·필드를 추론하지 않음 |

`NativeSchemaGraphIndex`의 경로·소스 fingerprint는 그 자체로 권한 부여 수단이 아닙니다. 그래프 스냅샷이나 후보 참조를 호스트 실행기에 호출 허가증처럼 전달해서는 안 됩니다.

## 4. 첫 제품 통합 설계

### 4.1 인터페이스와 역할

기존 개념 검색을 **명시적 opt-in 조합 함수**(가칭 `retrieve_authorized_concept_graph`)로 확장합니다. 새 `SchemaRouter` 인스턴스나 두 번째 검색 엔진을 만들지 않습니다. 입력은 다음과 같습니다.

- 명시적 권한 정책과 현재 등록된 원본 OpenAPI/MCP/OPTIMADE/사용자 정의 도구를 가진 `SchemaRouter`
- 원래 질의, 명시적 `PrincipalContext`, 호스트가 검토한 `NativeConceptCatalog`, **동일 레지스트리 버전**의 `NativeSchemaGraphIndex`
- 정확히 `k=5` 및 기존의 제한된 원본·필드 메타데이터 규칙

결과는 실행 권한이 없는 직렬화 가능한 선택 결과입니다. 명시적인 상태, 현재 소스 fingerprint·스냅샷 식별자와 완전한 경로 집합을 담거나, 후보 초과·모호성·권한 검증 실패 시 **빈 경로 집합**을 반환합니다. 각 경로 집합에는 등록된 정확한 경로 ID, 필요한 semantic ID, 완전한 생산자→소비자 파라미터 바인딩, 도구·엔드포인트 fingerprint를 유지합니다. 한 홉 경로는 서로 다른 원본 경로 두 개이므로 K 슬롯 두 개를 사용합니다. K는 그래프 경로 개수가 아니라 **모델에 노출되는 고유 원본 경로 개수**를 제한합니다.

상태는 `complete`, `no_proven_hit`, `over_k_unranked`, `budget_unsatisfied`를 구별합니다. 개념 선언이 없거나 충돌하는 질의는 안전한 입력 오류이며 일반적인 의미 기반 `NO_FIT`으로 보정해 주장하지 않습니다. 숨김·거부된 소스 이름과 개수, 비밀 필드 이름, 비공개 정책 증거는 사용자·모델 출력에 포함하지 않습니다. 신뢰 가능한 진단 기록에는 원문 질의나 숨긴 개수 대신 정제된 실패 단계 열거형만 남길 수 있습니다.

### 4.2 해석과 선택 순서

1. **호스트가 제공한** 개념 카탈로그의 버전·별칭을 검증하고 원래 질의에 명시된 개념만 해석합니다. 미지·중첩·충돌 개념은 안전하게 거부합니다. 필수 semantic ID에 타입·단위·한정자·출처·라이선스 제약을 모두 결합합니다.
2. 그래프와 레지스트리의 스냅샷 일치 여부, 요청자별 정책·가용성 증거를 확인합니다. 현재 접근 가능한 출력 필드만 요구 조건을 충족할 수 있습니다. 전역 그래프 검색 결과는 권한의 증거가 아닙니다.
3. 기존 `retrieve_authorized_field_group`에서 완전한 **직접 경로**를 찾고, 별도로 동일 FieldGroup을 사용해 `NativeSchemaGraphIndex.lookup`에서 타입이 검증된 **한 홉** 생산자→소비자 경로를 찾습니다. 식별자 연결을 임의 생성하거나 선언되지 않은 시작 경로 입력을 허용하지 않습니다. 입력이 필요한 시작 경로는 호스트의 명시적 승인과 완전한 신뢰 입력이 있어야 합니다.
4. 완전한 단일 엔드포인트가 있으면 우선합니다. 없으면 완전한 한 홉을 고려합니다. 이는 사전 선언한 보수적 정책이지 학습 순위·오라클·과제 우수성의 증명이 아닙니다. 동등하게 검증된 대안이 고정 예산에 들어오지 않으면 임의의 알파벳순 상위 5개를 고르거나 숨긴 개수를 노출하지 않고 `over_k_unranked`를 반환합니다. 선택된 경로의 모든 ID와 바인딩은 등록·가시성·완전성이 검증되어야 합니다.
5. 후보 계산 직후 및 외부 에이전트용 메뉴 구성 시 레지스트리 fingerprint, 실시간 정책·데이터 범위·가용성, 원본 입력 선언을 재검증합니다. 변경되면 중단합니다. 후보 결과만으로 `plan`, `execute`, 공급자 HTTP 요청, 모델 호출을 시작하지 않습니다.

직접 경로의 필드·작업 계약이 다르면 여러 단계 경로와 의미가 같다고 간주하지 않습니다. 하나의 완전한 FieldGroup은 **필드 검색**을 표현할 뿐, 복수 의도나 파괴적 워크플로의 완성을 보장하지 않습니다.

### 4.3 노출 예산과 실패 처리

- `k`뿐 아니라 실제 직렬화된 스키마·토큰 예산도 기록하고 강제합니다. 두 단계 경로라고 K5를 K6으로 늘리지 않습니다.
- 소스 바인딩, 인자 값, 호출·승인, 최종 에이전트 턴의 책임은 신뢰 호스트에 있습니다. 인덱스·별칭·모델 출력은 **새 권한을 전혀 부여하지 않습니다**.
- 검증된 대안이 K를 초과하면 첫 K개를 선택하지 않고, 독립 순위 증거가 나올 때까지 명시적인 초과 상태를 반환합니다.
- 요청자의 데이터 범위에서 숨겨진 필드를 참조하는 입력·출력 스키마 주석을 노출하지 않습니다. 안전한 투영을 증명할 수 없으면 보장을 꾸며 내지 않고 메타데이터를 생략합니다.
- 소스 변경, 경로 권한 철회, 신뢰할 수 없는 상태 콜백, 무효한 선언은 안전하게 중단합니다. 모델 출력만으로는 거부된 소스와 단순히 없는 소스를 비공개 경로 이름·개수로 구분할 수 없어야 합니다.

## 5. 통합 인수 기준과 실험

### 5.1 코드·기존 E0 검증 범위

구현 헬퍼마다 테스트를 늘리는 대신 다음 **통합 동작 테스트**를 작성합니다.

1. A 필드만, B 필드만 가진 형제 경로와 실제 A+B 완전 경로가 있을 때 K 적용 전에 완전한 타입 FieldGroup만 선택됩니다.
2. 이름만 같은 잘못된 타입·단위·한정자, 거부 경로, 숨김 중첩/ref 메타데이터, 가용성 철회, fingerprint 변경, 미지원 질의, 필수 입력 누락을 안전하게 거부하고 호출하지 않습니다.
3. 호스트 승인 시작 경로와 모든 원본 출력→입력 연결이 필요한 소비자에서 두 경로와 검증된 바인딩을 노출하고 부분 연결을 허용하지 않습니다.
4. 동일하게 입증된 경로가 K5를 초과하면 시작 경로를 공유하는 경우까지 임의 선택 없이 명시적으로 빈 후보를 반환합니다.
5. 같은 semantic ID로 선언된 EN/KO/JA 별칭과 미지원·모호 질의 대조군을 검증합니다. 번역 모델에 의미 권한을 부여하지 않습니다.
6. 선택 도중 원본 카탈로그 버전이나 요청자 권한이 바뀌면 일관되게 중단하고 오래된 캐시 권한 증거를 재사용하지 않습니다.

### 5.2 실제 과제와 비용 측정

첫 E1 개발 측정은 기존의 **실제 소스가 확인된 읽기 전용 Open-Meteo 두 작업 사례**를 사용합니다. 설치되고 버전이 고정된 모델·호스트·최종 정답 검증기를 재사용합니다. 기존 고정 K 인터페이스로 **FULL / lexical SR-5 / opt-in typed-G5**를 비교하되 모델, 요청자, 소스 구성, 질의, 디코딩, 엄격한 최종 검증, 실행 식별자를 동일하게 유지합니다. 원본 제공자 호출과 검증된 인자를 별도로 집계합니다. 모델 가중치 부재, API·네트워크 제한, 실시간 소스 응답 변화는 꾸며 낸 성능값이 아닌 실행 차단으로 기록합니다.

지원 과제마다 완전한 선택 경로 집합, 실제 호출 순서·인자, 공급자 성공·실패, 최종 사실 정확성, 모델 턴, 스키마 및 전체 입력 토큰, 측정된 CPU p50/p95/p99와 RSS, 실패 단계를 보고합니다. 지원 과제의 잘못된 거절과 실제 미지원·금지된 무호출 대조군을 구분합니다. 독립적으로 작성된 OOD 정답이 없으면 그 사실을 명시합니다. 공개 DEV 행에 임계값을 맞춰 개선한 후 확증 실험처럼 제시하지 않습니다.

**첫 통합 PR의 성공 기준:** 완전한 등록 개념·FieldGroup 요구가 최소한의 승인된 실제 원본 경로 집합(또는 안전하고 명시적인 거절)을 만든다는 것을 동작 테스트로 입증해야 합니다. 재현 가능한 E1은 기존 실패 과제를 권한 회귀 없이 하나 이상 완료하거나, **실패 단계와 누락된 실행 선행 조건을 정확히 보고하는 유효한 부정 결과**를 남겨야 합니다. 이를 근거로 기본 적용이나 독립 E2 개선을 주장할 수 없습니다.

**독립 검증 게이트:** 기본 적용, 상위 이슈 종료, 릴리스 전에 #1346에서 출처 사용이 허가되고 **공급자와 과제 작성자가 분리된** E2 데이터를 확보해야 합니다. 비교 및 성공·안전 한계를 사전 등록하고 #1477에 따른 대응 전체 과제 평가와 보안 회귀 검증을 수행합니다. 전까지 #1535/#1560/#1477은 구현이 진행됐더라도 E2 종료 조건이 미충족되면 열린 상태를 유지합니다.

## 6. 범위 제외와 이후 순서

이번 범위에서 제외합니다: `retrieve_authorized` 기본값 변경, 운영용 학습 그래프 순위, 교차 공급자 보정 `NO_FIT` 주장, 자동 두 홉·세 홉 오케스트레이션, 자격 증명·승인 프록시, 새 그래프 DB·LLM·하이퍼파라미터 탐색, #432 동결 결과 재해석, 승인되지 않은 실제 파괴적 호출, CodeGraph 도입(#1711), 통합 병목이 입증되지 않은 G5 CPU 미세조정(#1700).

통합 실측에서 근거 있는 부족이 확인되면 다음 단계는 #1339/#1403을 통해 별도 작성된 다국어 fit/no-fit 과제로 확장합니다. v0.18 PR #1356과 릴리스 게이트는 그대로 둡니다. 이미 적용된 #1700→M1과 #1711→M5 마일스톤 배정은 2026-10-19의 오래된 매니페스트와 일치하도록 정리하되, 일회성 초기화 Blob 보호 규칙을 유지하고 별도의 장부 정리 PR을 만들지 않습니다.
