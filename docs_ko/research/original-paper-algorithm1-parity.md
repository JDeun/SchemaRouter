# SchemaRouter 원 논문 Algorithm 1과 현재 제품 구현의 정합성 판단

**문서 성격:** 코드 대조·구현 우선순위 결정, **제품에서 논문을 완전히 재현했다는 선언이 아님**  
**작성일:** 2026-10-24  
**최상위 근거:** [원 논문의 LaTeX 본문](https://github.com/JDeun/paper_SchemaRouter/blob/main/paper/schemarouter.tex) (§1, §3–4 Algorithm 1, §6). 이후 CodeGraph 실험은 원래 사상의 대체 기준이 아님.  
**대상:** 2026-10-24에 확인한 `SchemaRouter/main`의 실제 검색·계획 코드.  
**기존 감사:** [#1530 코드 대조 기록](../../research/autoresearch/initial-paper-graph-retrieval-crosswalk-e0.md). 이 이슈의 종료는 **감사 종료**이지 논문 기능 완성 선언이 아님.

## 일반인을 위한 결론

**완전히 다른 프로그램을 만든 것은 아닙니다.** 여러 API의 도구·엔드포인트·입력값·출력 필드를 같은 타입 계약으로 등록하고, 질문에 맞는 기능을 검색·계획하며, 출처·단위·라이선스를 보존하고, 실행 권한을 다시 검증하는 시스템을 만들었습니다. 이는 원 논문을 실제 제품으로 만들기 위해 필요한 토대입니다.

**하지만 원 논문의 Algorithm 1이 제품 기본 검색 경로에 끝까지 연결된 상태도 아닙니다.** 현재 기본 검색은 `KeywordAnalyzer`와 어휘/타입 기반 Top-K입니다. 신뢰된 개념→FieldGroup→타입 그래프 검색은 **별도 선택 연구 기능**으로 구현됐습니다. 최근 생산자→소비자 그래프는 관련 있는 확장이지만, 질문의 의미를 정답에 필요한 **응답 필드**와 연결하는 원 논문의 스키마 그래프 전체를 대신하지는 않습니다.

원래 연구 목표는 **정답에 필요한 정보의 재현율을 보존하면서 실제 검색 결과 컨텍스트 비용을 줄이고 출처·단위·라이선스를 남기는 것**입니다. 도구 수·필드 수·스키마 메뉴 바이트를 무조건 최소화하거나 작은 LLM에게 다단계 도구 실행을 시키는 연구가 아닙니다. 논문에서도 너무 공격적인 필드 제거는 최종 정답 정확도를 0.71에서 0.56으로 낮춘다고 보고합니다.

### 원 논문의 기본 동작 과정

```text
사용자의 자연어 질문
  → 질문 이해: 의도, 개념, 인수, 출처 제약, 직접 지목한 도구
  → 신뢰된 스키마 그래프: 개념·별칭 ↔ 필수 필드 그룹 ↔ 엔드포인트
  → 출처·측정 정보·권한 조건에 맞는 후보 도구 선택
  → 재현율을 보존한 응답 필드 선택:
       식별자 ∪ 개념 대응 필드 ∪ 의도별 필수 필드 그룹
  → 단위, 출처 종류, provenance, license 부착
  → (도구, 인수, 응답 필드, 메타데이터) 실행 가능 계획 반환
  → 외부 RAG/에이전트가 실제 데이터를 받아 최종 답변 생성
```

현재 라이브러리에서는 후보 검색과 도구 실행 계획이 분리됩니다.
**후보 검색이 곧 실행 허가가 아닙니다.** 호스트가 명시적으로 실행을 요청한 뒤 스키마·원본·권한을 재검증하는 구조는 원 논문의 취지에 어긋나지 않는 보안 강화입니다.

## 원 논문 Algorithm 1 ↔ 현재 main 코드의 12항목 대조

| 논문에서 요구한 기능 | 현재 코드·구현 내용 | 판단과 남은 차이 |
| --- | --- | --- |
| **1. Tool → Endpoint → Parameter / ResponseField 스키마** | `models.py`의 `ToolSpec`·`EndpointSpec`·`FieldSpec`, `registry.py`, 각 소스 어댑터 | **기반 구현됨.** 그래프 DB를 반드시 설치해야 하는 것은 아님. |
| **2. 질문 이해(Understand)**: 의도, 개념, 인수, 출처 제약, 지목 도구 | 기본 `planner.py::KeywordAnalyzer`; 선택형 `analyzers/model.py::ModelQueryAnalyzer`; `PlanRequest`, `QueryIntent` | **부분 구현.** 작은 LLM 기반 원 논문식 의도 추출이 기본값이 아님. 선택형 모델 분석기에는 최대 128개 엔드포인트의 `schema_catalog`가 전달될 수 있으므로 논문의 *도구 개수와 무관한 고정 프롬프트*와 같지 않음. |
| **3. 사용자가 직접 지정한 도구 우선** | `_score_endpoint`가 preferred tool/endpoint에 높은 점수를 부여 | **관련 기능 있음.** 논문의 명시적 `Resolve` 우선 선택과 동일한 보장은 아님. 도구 부재·권한 거부 등의 별도 테스트 필요. |
| **4. Intent/FieldGroup 조건을 K 선택 전에 적용** | 기본 `_retrieve_from_intent`는 어휘·타입 검색 후 정렬하여 `candidates[:k]`; `retrieve_authorized_field_group`는 선택형 기능 | **핵심 기본 경로의 미완성 부분.** 필수 필드 집합 {A,B}의 전체 충족을 K 자르기 전에 반드시 검증하는 경로가 필요. **#1535** 담당. |
| **5. 출처, 단위, 한정자, 라이선스 조건** | `ToolSpec`/`FieldSpec` 메타데이터, `PlanRequest.evidence`, 타입 비교기, 선택형 FieldGroup | **부분 구현.** 등록 메타데이터는 존재하지만 기본 검색에서 항상 선행 필터로 쓰이는지는 조건별 테스트가 필요. 라이선스 문자열 등록은 법적 이용 허가를 뜻하지 않음. |
| **6. DomainConcept/별칭 → 정식 응답 필드** | 필드 `semantic_id/aliases`, 기본 `_score_endpoint`의 텍스트 매칭, 별도 `concept_retrieval.py`와 `concept_graph_retrieval.py` | **핵심 기본 경로 미연결.** 명시적 선언 기반 개념 검색은 있으나 기본 검색의 개념·필드 그룹 그래프 탐색과 동일하지 않음. 한국어·일본어 선언 별칭은 자유로운 다국어 의미 이해와 다름. **#1339** 담당. |
| **7. 필요 필드를 누락하지 않는 선택**: 식별자 ∪ 개념 필드 ∪ 의도별 필드 그룹 | `_project_fields`는 식별자와 매칭된 필드를 선택하고 답변 필드가 없으면 전체 출력 필드 보존 | **부분 구현.** 정답 손실 방지용 폴백은 좋지만, 의도에 필요한 FieldGroup을 명시적으로 더하는 논문 Algorithm 1과는 다른 구조. |
| **8. 필드별 provenance/license/unit 첨부** | `evidence.py::available_evidence`, `ToolCall.evidence`, `CapabilityCandidate` 및 `FieldSpec` | **계약 기반 구현.** 최종 답변에서 출처·라이선스를 실제로 표기하는 것은 외부 에이전트/reader의 책임. 제품 메타데이터 존재만으로 답변 신뢰성 실험을 통과한 것은 아님. |
| **9. 도구·인수·필드·메타데이터 계획 반환** | `runtime.py::plan`, `planner.py::_compile_candidate_sync`는 타입 기반 `ToolCall` 생성. `retrieve_authorized`는 실행 권한 없는 후보 반환 | **안전하게 분리된 API로 구현.** 실제 명시적 실행 요청 전에는 원본·권한·스키마를 확인하며, 통합된 논문 방식의 계획 생성도 별도 검증 필요. |
| **10. 도구 수에 영향받지 않는 작은 의도 분석 프롬프트** | 기본 키워드 분석은 도구 목록을 모델에 보내지 않음. 선택형 `ModelQueryAnalyzer`는 제한된 `schema_catalog`를 입력 | **모드별로 다른 구현.** 오프라인 키워드 분석이 저렴하다는 사실로 논문의 작은 LLM 고정 프롬프트를 구현했다고 주장할 수 없음. |
| **11. 생산자→소비자 필드 의존 그래프** | `capability_graph.py`, `native_graph_index.py`, 선택형 `concept_graph_retrieval.py`와 최근 #1741–#1744 | **유효한 확장 연구.** 도구 결과 식별자가 다음 도구의 필수 입력을 채울 수 있다는 관계는 유익하지만 원 논문의 *질의 개념→응답 필드* 그래프와 목적이 다름. |
| **12. 최종 답변 품질과 검색 비용의 동시 평가** | 원 논문: 재료 질의 110개, 최종 답변 정확도 0.71(상위 비교군 신뢰구간 겹침), 검색된 데이터 컨텍스트 227토큰 vs Fetch-all 2,066토큰, 출처 전용 라이선스 인용 62%. 최근 E0: 스키마 JSON 바이트 및 Qwen 토크나이저 토큰 | **현재 신제품의 독립 재현 미완성.** 서로 다른 과제·독자 모델·비용 단위입니다. 최근 약 30% *도구 설명 스키마* 토큰 감소는 원 논문의 *검색 결과 데이터 컨텍스트* 감소나 최종 답변 신뢰성 입증과 다릅니다. |

## 서로 다른 세 가지 그래프를 혼동하지 않기

1. **원 논문의 스키마 개념 그래프 — 최우선 목적.**
   자연어 개념·별칭을 정식 응답 필드와 필수 필드 그룹으로 연결하고 단위·출처·라이선스와 함께 필요한 엔드포인트를 선택합니다.
2. **기능 의존 그래프 — 제품 확장.**
   생산자 도구의 식별자·필드가 소비자 도구의 입력 조건을 만족시키는지 연결합니다. 타입 검증과 호출 경로 계획에는 중요하지만 첫 번째 그래프와 동일하지 않습니다.
3. **에이전트 실행·CodeGraph 프런티어 — 별도 응용 실험.**
   몇 번째 턴에 어떤 도구를 모델에 보여 주며 계속 실행할지 관찰하는 하네스입니다. 원 논문의 핵심 검색 알고리즘을 구현하지 않아도 존재할 수 있습니다.

## 만든 것이 잘못됐는가?

**아닙니다.** 여러 프로토콜 어댑터, 원본 타입 계약, 필드 우선 계획, 권한 검증, 불변 스키마 스냅샷, 안전한 도구 호출은 논문 알고리즘의 기반입니다. 없어져야 할 기술이 아니라 유지해야 할 자산입니다.

**다만 우선순위 이탈 위험은 있습니다.** 많은 어댑터·보안 기능·모델 에이전트 실험을 추가하면서도 정작 기본 질문→개념→필드 그룹→필수 응답 필드 검색 경로가 완성되지 않은 상태입니다.

그리고 연구 주장을 과대평가하면 안 됩니다. 기존 독립 #432의 FULL 49.62% 대비 SR-5 29.19%라는 부정적 결과와 한국어·일본어 초기 검색 실패가 여전히 존재합니다. 단일·복수 개발자 작성 합성 과제에서 나온 스키마 토큰 감소를 원 논문의 일반적 성능으로 확대하면 안 됩니다.

## 제품 개발 우선순위를 이렇게 다시 정렬

**P0 — 현재 제품 안전성 유지 / 용어 정리:** 안정판 0.17과 기존 검색·계획·실행 권한은 유지합니다. 스키마 바이트, 스키마 토크나이저 토큰, **검색된 결과 데이터 컨텍스트 토큰**, **에이전트 전체 입력+출력 토큰**을 별도 지표로 관리합니다. 세 가지 그래프는 다른 목적이라고 문서화합니다.

**P1 — 원 논문의 필수 필드 완전성(가장 먼저 구현, #1535):** 원본이 승인한 사용자 개념→의도→FieldGroup을 기존 권한별 검색 경계 안에서 해석합니다. K=5 후보를 자르기 전에 필요한 응답 필드 전체와 식별자/입력 바인딩을 타입·단위·한정자·출처·라이선스·현재 공개 가능한 필드 기준으로 확인합니다. 모호·미지원·권한 거부·필드 부족·K 초과는 허위 정답이 아닌 명시적 상태를 반환합니다. A만 있는 도구, B만 있는 도구, A+B 완전체, 단위 불일치, 숨김 B, 권한 거부 B, 식별자 타입 불일치, 필수 인수 누락, 다국어 선언 별칭을 별도로 테스트합니다. 기존 기본값은 바꾸지 않습니다.

**P2 — 논문 전체 계획으로 조립(#1560과 #1535):** 독립된 새 등록소나 에이전트를 만들지 않고 기존 `SchemaPlanner`, `ToolCall`, 원본 Registry와 그래프 인덱스를 재사용합니다. 선택형 논문 호환 경로에서 필요한 *식별자 ∪ 개념 필드 ∪ 의도 필드 그룹*과 바인딩된 인수·단위·출처·라이선스·원본 정책 증거를 가진 사용 계획을 구성합니다. 검색 후보가 실행 허가가 되지 않도록 합니다.

**P3 — 논문 수준의 평가 재구성(#1339, #1346, #1477):** 외부에서 작성한 과제·정답·권한 자료를 확보하고 동일한 질문·원본 스냅샷·에이전트/reader로 FULL, Prompt-all, 강한 어휘 검색, 선택형 논문 호환 그래프를 비교합니다. 필수 **응답 필드 재현율**, 올바른 인수·출처와 라이선스, 미지원 요청 거절, 실제 검색된 **데이터 컨텍스트 토큰**, 전체 지연, 최종 답변의 정답·출처 표기 비율을 검증합니다. 토크나이저 메뉴 비용과 전체 에이전트 비용은 별도로 기록합니다. #1346 독립 외부 데이터가 없다면 **BLOCKED_EXTERNAL**을 유지합니다.

**P4 — 기본값/릴리스 승격(#1560, #1356):** 독립 안전성, EN/KO/JA 언어 평가, 원본 출처 및 작업 완료율, CPU/RSS, 비용 비교를 통과한 뒤에만 검토합니다. v0.18은 **HARD HOLD**입니다.

## 새 이슈를 불필요하게 만들지 않고 기존 책임을 유지
