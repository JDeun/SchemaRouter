# CodeGraph 방식의 선택적 그래프 컨텍스트: 권한 범위가 고정된 E0 바이트 대조 실험

**검토: 2026-10-23 · [#1711](https://github.com/JDeun/SchemaRouter/issues/1711) · M5 · 합성 E0, 비실행 · 기본 동작 변경 없음**

## 선행 연구와 SchemaRouter의 차이 — 같은 문제로 취급하지 않음

| 질문 | [CodeGraph](https://github.com/colbymchenry/codegraph) | SchemaRouter |
| --- | --- | --- |
| 색인 대상 | 코드 기호, 호출 지점, 파일 관계, 코딩 에이전트 탐색 | 등록된 원본 도구의 작업, 출력 필드의 의미 ID, 타입이 있는 생산자→소비자 바인딩 |
| 의도하는 절감 | 반복적인 저장소 파일 탐색과 코드 위치 찾기 감소 | **동일한 원본 권한 검증 경로**를 유지하면서 모델에 보여 주는 중복 스키마 감소 |
| 신뢰 경계 | 개발자 로컬 코드 색인과 에이전트 통합 | 원본 fingerprint, Principal과 데이터 범위, 현재 권한 정책, 고정 K=5, 별도의 권한 검증 실행 주체 |
| 이전 가능한 아이디어 | **참조를 우선 보여 주고 필요한 세부 사항만 지연 제공하는 컨텍스트 구성** | 기존 `NativeSchemaGraphIndex`와 `retrieve_authorized_concept_graph` 재사용; 코드 AST 간선을 도구 실행 권한으로 수입하지 않음 |
| 범위 밖 | 원본 제공자가 보유한 기능 그래프의 대체재가 아님 | 새 AST 색인·그래프 DB·학습된 간선·에이전트 호출기·기본 라우터·권한 우회 없음 |

**선행 연구의 출처:** `colbymchenry/codegraph` MIT 라이선스(`LICENSE` Git blob `31c84c9c80d953a0571b69af15cf815f22c5f2b6`). 2026-10-23에 확인한 README의 Git blob은 `baac93178c98b6efb9794a5668d42f3f0f0882f7`입니다. README는 2026-08-05, 7개 저장소에서 조건별 4회 수행한 자체 아키텍처 QA를 근거로 **도구 호출 88% 감소, 처리 토큰 62% 감소, 비용 44% 감소**를 보고합니다. 이는 **SchemaRouter의 성능 측정이 아닙니다.** 또한 해당 README는 여러 턴의 누적 처리 토큰은 적었지만 **남아 있는 컨텍스트 점유량은 더 클 수 있음**을 명시합니다. 따라서 직렬화한 바이트 수만으로 실제 에이전트 컨텍스트 창, 도구 호출 효율이나 비용을 예측할 수 없습니다. [원문 벤치마크 방법](https://github.com/colbymchenry/codegraph#benchmark-results).

## 사전 등록한 고정 E0 대조 실험

**가설:** 검증된 타입 그래프의 경로 참조는 유지하고 *모델에 공개할 전체 도구 정의*를 필요할 때까지 미루면, 경로·바인딩·가시 필드·원본/권한 상태를 바꾸지 않고 초기 직렬화 바이트를 줄일 수 있습니다. **반증 조건:** 권한 없는 경로 또는 오래된 경로가 살아남거나, 원본·경로·필드의 증명이 달라지거나, 지원되는 실험에서 바이트 이점이 없다면 가설을 기각합니다. 바이트 감소만으로 모델 적용을 승인하지 않습니다.

- **비교 단위:** 질의 1개 × 합성 원본 카탈로그·색인의 동일한 스냅샷 × Principal 1개 × 고정 `K=5`. 두 조건은 **동일한** `NativeConceptGraphSelection`과 권한 검증된 `capture_authorized_agent_tool_surface`를 사용합니다. 새로운 계획기를 추가하지 않습니다.
- **FULL:** 선택 경로의 증명 정보와 선택된 원본 도구의 Principal 범위 정의(이름·설명·매개변수 스키마).
- **SURGICAL:** 상태·스냅샷/버전·경로 ID·각 경로 및 도구/엔드포인트 fingerprint·생산자 필드→소비자 매개변수의 **완전한 바인딩**·필수 의미 ID·보이는 출력 이름·거짓인 품질/권한 플래그를 FULL과 **완전히 동일하게** 유지합니다. 대신 도구 정의를 제거합니다. `requires_source_schema_materialization=true`, `tool_call_ready=false`는 실행 가능한 도구가 아니라는 뜻입니다.
- **보안:** 검증된 모델 표시 화면에 선택 경로가 존재해야 하고 원본 fingerprint도 일치해야 합니다. 그래프 선택과 별도 도구 화면 조회 **전체 구간에 걸쳐 원본/권한 witness, 정책 내용 receipt, 정규화된 Principal 클레임을 재검증**하며, 조회 결과에 생산자 바인딩 필드가 실제로 보여야 합니다. 중간의 권한 정책 교체·제자리 변경, Principal 변경, 오래된 원본은 모두 실패로 처리합니다. 결과가 없는 상태에도 동일한 검사를 수행합니다. 다만 이는 여러 호스트 스레드에 걸친 원자적 트랜잭션을 보장하지 않습니다. `no_proven_hit`·거부·over-K에서는 상태를 유지하고 **경로 ID는 0개**입니다. 숨긴 후보 정보를 노출하거나 Top-5를 임의 절단하지 않으며, 범용 공개 API를 추가하지 않습니다.
- **실험 집합:** 필수 루트 식별자 2개를 출력하는 원본 CRM 생산자와 그 두 입력이 모두 연결된 소비자 1개. 소유자가 선언한 EN/KO/JA 별칭을 각각 적용합니다. 식별자가 부족한 생산자(`no_fit`), 접근이 거부된 Principal(`denied`), 적격 소비자 6개(`over_k`)도 측정합니다. 원본 호출·사용자 페이로드·모델 정답·실행 에이전트는 없습니다.
- **측정:** 양쪽에서 동일하게 `len(json.dumps(payload, sort_keys=True, ensure_ascii=False, separators=(',', ':'), allow_nan=False).encode('utf-8'))`를 사용하고 `SURGICAL/FULL` 비율을 구합니다. 동일 호출의 결정성, 경로 동등성, 전체 증명 필드를 검사합니다. 토크나이저나 LLM을 돌리지 않으므로 **처리 토큰·실제 비용·후속 도구 호출·최종 작업 성공은 모두 측정하지 않았습니다(NOT MEASURED).**

저장소 루트에서 재현할 수 있습니다.

```bash
python -m scripts.research_codegraph_surgical_context_e0 --json
python -m pytest -q tests/test_research_codegraph_surgical_context_e0.py
```

원본과 조건이 일치하는 지원 사례는 **797바이트(43.67%)** 감소했습니다. 이는 모델 토큰 감소가 **아닙니다**. 실패/빈 결과에서는 참조를 나중에 구체화해야 한다는 표시 때문에 **22바이트가 오히려 증가**했으므로 절감 사례가 아닙니다. 반복 비교에서 바이트와 바인딩은 동일했습니다. 테스트는 그래프 선택 직후 권한 범위를 좁히는 경우(정책 객체 교체와 제자리 변경 포함), 중간 Principal 변경을 차단하며, 원본 개정 후 낡은 색인 실패와 새로운 색인 스냅샷 ID 변화도 확인합니다.

FULL도 그 자체로 **도구 실행 권한을 의미하지 않습니다**. 실제 실행에는 독립된 호스트의 정책·인자·원본 검증이 필요합니다. SURGICAL은 매개변수 JSON Schema를 포함하지 않아 **직접 함수/도구 호출 인터페이스로 사용할 수 없습니다**. 추후 지연 구체화 기능을 만든다면 원본·권한 재검증과 비용 기록이 있는 별도 프로토콜이어야 합니다. 현재 실험에는 그 비용이 포함되지 않으므로 실제 통합 절감률을 과장할 가능성이 있습니다.

## 진행/중단 결정과 다음 연구

**E0 판정: 작은 합성 대조군에서 바이트 효과는 관측했지만 실제 모델/제공자 효율로 이전되는지는 검증되지 않았습니다.** #1711은 관련 검토가 끝날 때까지 M5에 유지합니다. 고정 K, 출고 기본값, 독립 no-fit 판단 및 #1356 출시 보류 상태를 변경하지 않습니다. CodeGraph가 자체 보고한 성능을 이 프로젝트에 적용된 결과라고 주장하지 않습니다.

**별도의 다음 E1 결정:** 동결한 동일한 원본 제공자 목록·권한 범위·Principal·예산에서 FULL, lexical SR-5, typed G5, 선택적 참조 구성을 실제 모델/에이전트로 비교해야 합니다. 실제 토큰 증명·도구 호출·지연·작업 성공(EN/KO/JA 및 미지원 요청), 원본 제공자 호출 실패, 불변 원본 증거, 결과가 비교 불가능할 때의 명시적 판정을 기록합니다. #1346의 제공자 분리 독립 E2는 별도 조건이며 E0로 추정할 수 없습니다.
