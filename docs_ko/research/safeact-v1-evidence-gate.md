# SafeActBench V1 증거 게이트 평가

추적 이슈: #1211

이 연구는 공식 SafeActBench V1 단일 행동 프로토콜에서 SchemaRouter를 **실행 계층 개입(execution-layer intervention)**으로 평가합니다. 증거 게이트를 적용한 실행을 에이전트의 본래 행동으로 해석하지 않습니다.

## 상위 프로젝트 버전 고정

- 저장소: `caoshidong66/safeact`
- 리비전: `841816cf1e376e6fbf8600cffac5df1736e1d369`
- 프로토콜: V1
- V1 사례 수: 131
- 코드 라이선스: MIT
- 벤치마크·환경 데이터 라이선스: CC BY 4.0

공식 벤치마크는 6개 도메인, 5개 프로토콜의 656개 사례로 구성됩니다. V1에서는 실행하기 전에 필요한 증거가 확보되어야 하는 중요한 단일 행동을 다룹니다.

## 저자 피드백 반영

Hongzhan Lin은 2026-10-08 직접 회신에서 신뢰 가능한 타입 기반 증거 계약이 SafeActBench의 증거에서 행동으로 이어지는 관점과 개념적으로 부합한다고 확인했습니다. 동시에 다음 두 가지 제약을 강조했습니다.

1. SchemaRouter는 게이트를 적용하지 않은 에이전트의 행동을 직접 측정하는 도구가 아니라 **실행 계층의 개입 조건**으로 평가해야 합니다.
2. 게이트에 SafeActBench의 비공개 정답 요구사항을 사용해서는 안 됩니다. 독립적으로 정의한 신뢰 가능한 계약과 실행 중 실제 확보한 증거만 사용해야 합니다.

저자는 V2/V3에 앞서 V1부터 시작하고, 특히 근거 없는 실행·성급한 행동 시도·전체 작업 성공률·잘못된 거부를 측정하도록 권고했습니다.

## 비교 조건

1. `SAFEACT-UNGATED`
2. `SAFEACT-SCHEMAROUTER-NO-EVIDENCE-GATE`
3. `SAFEACT-SCHEMAROUTER-EVIDENCE-GATE`

조건 간 비교에서 모델, 실행 하네스, 작업 순서, 공개된 작업·도구 표면, 평가기 리비전은 동일하게 유지해야 합니다.

실행 준비용 `V1RunPlan`은 현재 Python 인터프리터에서 공식 실행기를 절대 경로로 호출합니다.
`validate_comparison_matrix()`는 사전 등록한 세 조건이 정확히 한 번씩 포함되고,
동일한 모델 식별자와 고정된 상위 저장소 체크아웃을 사용하며, 결과 디렉터리가
분리되어 있는지 검증합니다. 이는 **선언한 실험 설계**를 검증하는 것이며,
실제 실행 모델과 사례별 환경은 점수 산출 전에 신뢰 가능한 어댑터가 별도로
증명해야 합니다.

## 정답 정보 누출 방지 경계

런타임 계약 생성에서는 독립적으로 신뢰할 수 있으며 에이전트에 공개된 capability 및 정책 표면만 읽을 수 있습니다. 평가기 전용 정답 요구사항이나 지원 여부 레이블을 읽어서는 안 됩니다.

런타임에서 사용이 금지되는 입력에는 다음 항목이 포함됩니다.

- `env/case_evidence.json`
- `env/case_manifest.json`에 포함된 평가기 전용 요구사항
- `env/case_provenance.json`
- 구체화된 증거(materialized evidence)에 포함된 정답 요구사항 주석
- 예상 행동·지원 여부 레이블, 정답 결정, 평가기 요약

공식 평가기는 궤적 실행이 모두 끝난 **이후에만** 비공개 또는 평가기 전용 자료를 사용할 수 있습니다. 그러한 정보가 행동 실행 여부를 결정하는 증거 계약(Evidence Contract)이나 증거 원장(Evidence Ledger)으로 다시 유입되어서는 안 됩니다.

## 평가 지표

1차 지표는 각각 분리하여 보고합니다.

- 근거 없는 실행 비율(unsupported execution rate)
- 성급한 행동 시도 비율(premature action attempt rate)
- 정확한 사례 성공(Exact Case Success) 및 전체 작업 성공률
- 잘못된 거부 비율(false refusal rate)

2차 진단에는 증거 충족 행동 비율, 관찰 가능한 경우의 출처 정확성, 인자·스키마 유효성, 게이트 작동 횟수·사유, 지연 시간 및 컨텍스트 비용을 포함합니다.

## 실행 승인 조건

아래 조건이 모두 충족되기 전까지 V1의 점수 산출 실행을 허용하지 않습니다.

- 독립적으로 작성한 V1 계약이 존재할 것
- 계약의 출처를 기계적으로 검증할 수 있을 것
- 평가기 전용 필드가 런타임 계약·원장에 유입될 수 없다는 회귀 테스트가 존재할 것
- SafeAct 어댑터가 공식 평가기의 정보 경계를 보존할 것
- 상위 SafeAct와 SchemaRouter의 정확한 리비전을 고정할 것

## 신뢰된 세션의 소스 파일 무결성 확인

`from_verified_sources(..., source_root=...)` 팩토리는 사례별 세션을 시작하기
**전에** 고정된 SHA-256 내용과 로컬 경로의 안전성을 검사합니다. 신뢰하는 루트는
모델이 아닌 상위 하네스에서 지정해야 합니다. 기본 생성자는 메커니즘 테스트용으로,
실제 소스 파일의 무결성을 검증하지 않습니다. 이 검사만으로 독립적 작성이나
공식 벤치마크 점수의 유효성이 증명되는 것은 아닙니다.

## 공식 세 조건 실행 후 무결성 감사

외부 에이전트의 실행 궤적과 공식 평가를 모두 완료한 후에는
`scripts/verify_safeact_v1_comparison.py`에 사전 등록된 세 조건별 출력
디렉터리를 전달합니다. 이 감사기는 시뮬레이터 출력, 누락·재사용된 사례,
불일치하는 사례 지문, 서로 다른 실제 모델, 비격리 세션,
공식 아티팩트 해시 변조를 거부합니다. 공식 성공률을 비교하기 전에
V1 **131개 사례 전체**를 검증합니다.

별도 `scripts/aggregate_safeact_v1_metrics.py`는 세 실험 조건을 모두
검증한 **이후에만** 공식 V1 사례별 평가 기록으로 정확한 사례 성공률과
게이트 이후 기록에 남은 **비-ALLOW 행동의 비율**을 계산합니다. 시뮬레이터 출력이나 불완전한
기록은 거부하고 공식 전체 성공률과 다시 대조합니다. 게이트에서 차단한 모델의 시도는 공식 평가 기록에서 제거될 수 있으므로 이 비율을
**원래 모델의 성급한 행동 시도율**이나 **근거 없는 실행율**로 해석해서는 안 됩니다. 근거 없는 실행 비율과 잘못된 거부 비율은 신뢰 가능한
실행·차단 기록 및 반사실적 정당성 검증이 마련되기 전까지 미측정으로 표시합니다.
정답 및 평가기 아티팩트는 실행 궤적이 종료된 **이후에만** 검사하고,
행동 증거 게이트의 입력으로는 사용하지 않습니다.

## 타입 기반 라우팅 전용 공식 V1 어댑터

`official_routing_hook.py`는 별도의 호스트 측 라우팅 전용 비교 조건을 제공합니다.
에이전트에 공개된 고정 후보 도구로부터 실제 SchemaRouter `ToolSpec`,
`EndpointSpec`, `InMemoryRegistry`를 구성합니다. 정보 조회 결과는 유지하면서
공식 실행 기록에 반영하기 전에 변경 작업의 도구 식별자와 객체 형태의 인자를
확인합니다. SafeAct 평가기 레이블은 사용하지 않으며, 예제 인자 값으로부터
상세 파라미터 스키마를 추론하거나 증거 요건을 집행하지 않습니다.
`schemarouter_typed_route` 표시를 통해 기본 조건 및 증거 게이트 조건과
사후 구분할 수 있습니다.

8개 사례의 통제 회귀 실험은 실제 `EvidenceGate` 구현으로 판단하고 고정된
합성 사례 기준 결과와 비교합니다. 이는 **SafeActBench 모델 실험이 아닙니다.**
공식 131×3 점수 산출에는 독립적인 사례별 계약 검토, 신뢰된 Codex/Claude
모델 브로커, 세 조건의 실행 개입 무결성 검증이 여전히 필요합니다.

## 행동 대상과 증거 레코드 바인딩

독립적으로 작성한 계약은 `argument_bindings`로 변경 작업 인자(예: `charge_id`)를
`required_observations`에서 이미 요구하는 레코드 ID에 연결할 수 있습니다.
증거 게이트는 호출 전에 행동 인자와 **이전에 실제 관찰한 증거**를 모두 확인합니다.
`C2`의 증거로 `C1`을 변경할 권한을 부여해서는 안 됩니다.

레코드 요구사항에는 독립적으로 정의한 `"$action.charge_id"` 형태도
사용할 수 있습니다. 실행 시 게이트는 현재 행동의 `charge_id` 인자만으로
대상 ID를 해석하고 이전에 신뢰된 도구 결과에서 관찰한 같은 레코드를
검증합니다. 인자가 없거나 문자열이 아니면 실행을 거부합니다. 따라서
평가기 전용 정답 레이블 없이도 동일한 정책 템플릿을 여러 공개 V1 사례에
적용할 수 있습니다.

이 기능은 결정론적 회귀 테스트로 검증한 게이트 구성 요소이며
SafeActBench 점수로 보고할 수 없습니다. 점수 산출을 위해서는 신뢰 가능한 도구 관찰
어댑터와 독립적으로 작성한 V1 계약이 여전히 필요합니다.

기존 8개 사례의 Evidence-to-Action 시드 테스트는 결정론적 메커니즘·회귀 검증 자료일 뿐이며, SafeActBench 성과로 해석하거나 보고하지 않습니다.

## 사례 ID와 분리된 증거 계약 선택 방식 사전 개정안(#1268, 미실험)

기존 초안의 `case_coverage[case_id] -> 예상 행동` 매핑은 공식 V1의
공개 사례 ID 목록만으로 정당화할 수 없는 **사례별 정답 행동**을 요구합니다.
비공개 정답이나 평가기 사례 매니페스트를 사용해 이 매핑을 채워서는 안 됩니다.
수정된 초안에서는 **131개 공개 ID 전부를 실험 집단·조건 간 매칭에만 사용**하고,
`case_coverage`의 값은 모두 `null`로 유지합니다.
증거 게이트는 실제로 모델이 제안한 변경 도구의 식별자에 해당하는 계약을
선택하고, 독립적으로 고정된 공개 도구·정책 소스에서 정해진 증거 요건을
확인합니다. 등록되지 않은 행동은 공식 실행 기록에 반영하기 전에 차단합니다.
이는 점수 산출 전 연구 방법의 개정이므로 계약 작성자와 별도 독립 검토자의
승인을 받아야 합니다. **아직 SafeActBench 공식 점수로 평가한 결과가 아닙니다.**
[추적 이슈 #1268](https://github.com/JDeun/SchemaRouter/issues/1268)을 참고하십시오.

## 도메인과 행동을 함께 지정하는 계약 선택(사전 개정, 미실험)

SafeActBench의 서로 다른 공개 도메인에는 `reply_send`처럼 이름이
동일한 도구가 존재할 수 있습니다. 따라서 도구 이름만으로 전역 실행
권한을 결정할 수 없습니다. 수정된 V1 호스트는 상위 저장소의
**공개 시나리오**에서 `env_id`를 읽고,
**(`env_id`, 모델이 제안한 변경 도구)** 쌍으로 독립 계약을 선택합니다.
도메인을 모델의 임의 응답, 불투명한 사례 ID 또는 평가기 전용 정답에서
유추해서는 안 됩니다. 도메인이 없거나 알 수 없는 경우 실행을
차단하며, 다른 도메인의 동명 계약으로 행동을 허가하지 않습니다.
동일한 이름의 도구라도 도메인이 다르면 별도의 공개 정책·증거
요구사항과 독립 검토가 있어야 합니다. 공식 실행 준비 검사는 유효하지
않은 도메인이나 같은 도메인·행동 쌍이 중복된 계약을 거부합니다.

이는 공식 점수를 산출하기 전에 보강한 무결성 보호 장치이며
**SafeActBench 모델의 새 평가 결과가 아닙니다.** 도메인별 계약
작성·독립 검토, 원본 해시 고정, 신뢰하는 Linux 실행 환경 및
명시적 실험 승인은 여전히 필수입니다. 관련 이슈: #1268, #1224.


## 도메인별 신뢰 증거 추출(사전 개정, 미실험)

도메인과 모델이 제안한 행동으로 계약을 선택하더라도 다른 도메인에
존재하는 동명 정보 조회 도구의 증거 추출 규칙을 사용해서는 안 됩니다.
이에 `public_observation_mappings`는
`env_id → 정보 조회 도구 → {record_id_key, field_name_key}` 구조로
제한합니다. 신뢰된 공식 호스트는 상위 저장소의 공개 시나리오에서만
`env_id`를 가져옵니다. 도메인이 빠진 평면형 매핑은 거부하고,
실행 준비 검사는 각 행동 계약의 모든 필수 조회 도구에 대해
**동일한 도메인**의 적절한 추출 규칙이 존재해야 통과합니다.
이는 점수 산출 전 설정의 안전성을 강화한 것이며, 독립적인 정책
작성·의미 검토·실제 모델 평가의 완료를 의미하지 않습니다.


## 공개 조회 결과의 값 완전성 검증(점수 산출 전)

고정된 SafeAct V1 공식 호스트의 공개 사실 정보는
`subject`, `predicate`, `object`로 구성됩니다. 조회 결과에
필드 이름이 있어도 실제 값이 누락되거나 `null` 또는 공백이면
해당 조회를 실행 허가용 증거로 인정하지 않습니다.
`call_id`가 비어 있을 때도 인정하지 않으며, 의미가 있는
불리언 `false`와 숫자 `0`은 정상 값으로 취급합니다.
이는 모델을 호출하지 않는 구조적 안전 검사입니다.
**필드를 관측했다는 사실만으로 그 값이 정책의 조건을 충족했다는
뜻은 아닙니다.** 환불 가능 금액 비교 등의 실질적 정책 조건은
독립적으로 작성·검증·승인해야 합니다.


## 공개 관측값의 선언형 비교 조건(점수 산출 전, 미승인)

도메인별 행동 계약에는 독립적으로 작성한 `value_conditions`를
선택적으로 추가할 수 있습니다. 연산은 `eq`, `lte`, `gte`만
허용하며, 각 조건은 실제 조회 도구, 행동 인자에 연결된 대상 레코드,
공개 관측 필드를 명시해야 합니다. `action_argument`는 비교의
왼쪽 값, 신뢰된 조회 결과의 실제 필드 값은 오른쪽 값입니다.
예를 들어 환불 요청 금액이 조회된 허용 금액보다 작거나 같은지를
비교할 수 있습니다.

```json
{
  "value_conditions": [
    {
      "tool": "charge_read",
      "record_id": "$action.charge_id",
      "field": "amount",
      "operator": "lte",
      "action_argument": "refund_amount"
    }
  ]
}
```

`action_argument` 대신 공개 정책에 근거한
스칼라 `literal`을 지정할 수 있지만 둘을 함께 지정할 수 없습니다.

게이트는 실제 호스트 `ToolGateway`의 완료된 조회 결과에서
얻은 값만 사용합니다. 관측값 누락, 동일 필드의 상충하는 값,
대상·도메인 불일치, 숫자로 해석할 수 없는 비교값, 허용되지 않은
표현식과 조건 위반은 모두 실행을 차단합니다. 불리언 `false`와
숫자 `0`은 증거 누락과 구별합니다. 단위, 화폐, 시간 범위 및
정책 예외의 적합성은 독립 작성자·검토자가 별도로 확인해야 합니다.
**이 기능 구현은 131개 사례의 계약 작성·독립 승인이나 실제 공식
모델 평가 완료를 의미하지 않습니다.** 관련: #1269, #1224.
