# SchemaRouter 0.18.0

SchemaRouter 0.18.0 focuses on **explicit no-match authority, declared multilingual capability metadata, optional decision-backend validation and reproducible external source checks**. The Python package remains a typed capability retrieval and governed execution library, not a general-purpose agent orchestrator or automatic translation system.

## Routing and no-match control

- The explicit, opt-in principal-bound selective execution gate (`ainvoke_selective` and related contracts) can reject unsuitable, unsupported or stale authorized shortlists **before planning or calling tools**. The host must supply independently calibrated policy thresholds; ordinary `retrieve()` and `ainvoke()` do **not** automatically become calibrated semantic abstainers.
- Lexical retrieval now considers **declared endpoint operation aliases** in indexed and exhaustive paths. Japanese scripts are tokenized alongside existing Latin/Korean terms, enabling matching **declared** localized field aliases. Neither change translates unknown queries or creates missing tool capabilities.
- Candidate provenance, registry identity, execution authorization and source-bound policy are independently revalidated before invoking a selected endpoint. A nonempty Top-K list is **not** proof that the request is supported or that execution is permitted.

## Optional decision-backend integration

- A host-configured Microsoft Foundry Decision-1 HTTP adapter is available as an **opt-in candidate**: HTTPS origin, explicit credentials and deployment name, finite-choice output, validated declared option IDs and `none_of_above` abstention. It refuses malformed credentials, payloads, probabilities, usage and excessive responses. This is adapter/contract validation, **not** an independently verified live Microsoft model quality result.
- Laya finite-choice and System One response parsing now fail closed on coerced Boolean/number choice IDs, invalid confidence, inconsistent probabilities and non-choice responses.
- Jev native result-contract and upstream protocol evidence guards reject malformed/unverifiable activation results; these do not imply a paid Jev or true Laya-model benchmark was executed.

## External development evidence — scope matters

Reproducible **development-only** source and benchmark safeguards were added for ClicShopping, ServiceNow and SmartMCP; Clear Your Tools component/loopback work and HYSET public-input readiness remain separate, narrow evidence. These are neither independently authored cross-project held-out results nor production/provider authorization tests.

- ClicShopping's corrected source is available from a SHA-identical public fork; its verified 32+10 **visible DEV** cases still included unsupported queries with nonempty candidates.
- ServiceNow's visible `readonly` 12-tool DEV comparison showed static required-tool recall **100%**, SchemaRouter K3 **75%**, K5 **85%**; no independent confirmation is claimed.
- HYSET's original paper `best.pt` is unavailable, so its no-model preflight is not a model reproduction; the full CYT agent and native pi-jev/local Laya comparisons also remain unconfirmed.
- The pre-release external evidence inventory separates locally verified smoke/DEV status from unresolved author approval, independent gold labels, real model runs and held-out scientific authority.

## Research integrity and measurement

The frozen 0.14 results remain **negative for their preregistered product-quality claims**: #432 held-out full-catalog task completion exceeded every deployable shortlist condition; #424 final factual answer gates failed; #506 output-field projection reduced context yet did **not** meet the unsupported-fact noninferiority gate. No 0.14 row, threshold or outcome has been retroactively changed.

Prospective tests now explicitly distinguish **tool-task completion** from **grounded final-answer success**. A deterministic installed-wheel regression comparing the authentic `0.17.0` wheel with the release-candidate wheel tests declared aliases and unsupported controls; it is **not** an independent multilingual end-to-end performance comparison. A new independent released-wheel confirmation, if undertaken, is tracked after publication under #1344.

## Compatibility, safety and migration

- Existing deterministic routing, principal/authorization checks and ordinary public entrypoints remain the default.
- Opt into the new no-match execution policy only with validated source/registry/principal context and externally justified thresholds; no default calibration or automatic provider/model selection is supplied.
- Optional hosted Foundry integration requires the host's explicit HTTPS endpoint/deployment/credential configuration and may incur provider charges. It does **not** grant endpoint execution authority.
- Stricter malformed-response and provenance checks may reject inputs previously coerced or accepted. Callers relying on loose Boolean/string/numeric coercions should produce the declared types instead.
- Consult the [release checklist](../release-checklist.md) and [versioning policy](../versioning.md) for distribution provenance and exact installed-wheel smoke gates. GitHub Release / PyPI hashes are established by the release manifest, not asserted by these notes.
