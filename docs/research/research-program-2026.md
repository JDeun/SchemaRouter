## 1. Mission and scope

**Primary research question:** Can a source-attested, typed, authorization-scoped schema graph expose only the necessary Tool/Endpoint/Parameter/ResponseField capabilities to an external agent, at bounded K and schema/context cost, **without sacrificing full task completion, correct no-fit abstention, or execution safety** compared with a full-catalog baseline?

The boundary is **capability discovery and governed typed execution**, not a new autonomous agent, LLM gateway, translation model, benchmark oracle, graph database, or tool-invoker replacement. Keep the **one canonical registered catalog** across OpenAPI, MCP, OPTIMADE, Python and other native sources. Query-concept-to-FieldGroup matching, producer-to-consumer edges and source/permission proofs may narrow candidates, never create permission. External host/agent retains actual model behavior and call proposal; trusted execution revalidates authority, arguments, source and observations.

The original [SchemaRouter paper](https://arxiv.org/abs/2608.21375) reports a 110-question domain study, not a guarantee on unseen heterogeneous 5k-tool catalogs or downstream agents. The frozen independent 0.14 experiment is an important **negative**: FULL 49.62%, SR-5 29.19%, SR-10 31.03%, SR-PROGRESSIVE 25.09%, ORACLE 70.98% task success (Issue [#432](https://github.com/JDeun/SchemaRouter/issues/432), failure analysis [#1339](https://github.com/JDeun/SchemaRouter/issues/1339)). Never rewrite that outcome when later exposed development scores improve.

### 2026-10-22 integrated G5 opt-in slice: implemented boundary vs E1 blocker

**Product implementation (opt-in):** `schemarouter.retrieve_authorized_concept_graph` composes the existing owner-declared `resolve_native_concepts` → complete authorized FieldGroup retrieval → exact-version `NativeSchemaGraphIndex.lookup`. It returns immutable `NativeConceptGraphSelection` with `route_sets`, native tool/endpoint fingerprint triples, declared semantic output IDs and all proved original producer-field→consumer-parameter bindings. A complete **input-free direct** endpoint is preferred. An endpoint whose required inputs are not satisfied is **not** promoted to an input-free direct route; it must be supported by the existing complete typed one-hop join. Both are discovery-only: `executable_authority=False`.

The exact opt-in wiring, in an explicitly principal-authorized host with already reviewed source metadata, is:

```python
from schemarouter import (
    NativeSchemaGraphIndex,
    NativeSchemaPostingIndex,
    retrieve_authorized_concept_graph,
)

# router: existing SchemaRouter with explicit authorization_policy and native source tools
# catalog: owner-reviewed NativeConceptCatalog with EN/KO/JA aliases and exact typed fields
# principal: existing PrincipalContext scoped to this request
index = NativeSchemaGraphIndex.build(NativeSchemaPostingIndex.build(router.registry))
result = retrieve_authorized_concept_graph(
    router, "문의 상태", principal=principal, catalog=catalog, index=index, k=5,
)
if result.status == "complete":
    print(result.route_ids)  # Authorised native *route IDs*, not a tool-call grant
```

This example presumes the original host has genuinely declared `"문의 상태"` in the catalog; SchemaRouter **does not translate or infer it**. Equivalent owner-declared EN/KO/JA aliases resolve to the same typed constraints. `no_proven_hit` reveals no hidden identities; if more than five **distinct route IDs** are needed by complete alternatives without verified ranking, `over_k_unranked` returns **no routes**, never an arbitrary Top-5. The graph index, registry revision, policy/data scope, availability, native fingerprints and catalog contents are rechecked, and neither queries nor discovery results authorize invocation. This first slice supports **direct + one-hop**, not automatic multi-hop orchestration.

**Agent integration:** `AuthorizedConceptGraphFixed5Selector` extends the existing callback in `scripts/research_authorized_concept_fixed5_agent_bridge.py` and plugs into the pre-existing `EVAL-FIXED5-OPTIN` generated-agent path. Only `AuthorizedAgentToolSurface` definitions scoped to the principal, original query and exact source revision are shown. The selector verifies live policy content, hidden/ref-safe field projections, all selected source fingerprints, K5 and actual serialized tool-definition byte budget. The previous concept selector and ordinary retrieval defaults remain unchanged. Controlled E0 integration tests showed that an agent using the existing loop can see both producer and consumer routes and complete two calls, but those model-stub/fixture outcomes **are not native E1 or independent E2 evidence**.

**Native E1 preflight:** `scripts.research_real_qwen_open_meteo_two_hop_e1` has an explicitly named `concept_graph_optin` and `compare_graph_native_e1` comparison with `all_visible` and `lexical_k5`. It reuses the original Open-Meteo source invokers, source-state checks and strict final factual scorer. Run source qualification only (without loading model weights or calling the provider):

```bash
PYTHONPATH=src:. python -m scripts.research_real_qwen_open_meteo_two_hop_e1 \

These values are the host's reviewed declarations, **not** inferred from E1 queries or evaluation gold. The E1 module revalidates the live original source/policy/typed graph before any call, and loads pinned model weights **offline only** after this qualification passes. Passing flags alone never cures an unattested source.

## 2. Research architecture and non-negotiable invariants

1. **Ground truth of capability:** registered source-native schema, exact endpoint fingerprints, reviewer-approved semantic IDs, units, license, source version, and typed input/output constraints. Unreviewed descriptions and LLM-extracted intent confer **no** new authority.
2. **Discover:** independently resolve query concepts to conjunctive FieldGroups; compute complete authorized and data-scope-visible candidates **before K**. Use the original `capability_graph.py` typed compatibility graph and existing G5 index, not a second graph/router. No arbitrary Top-5 cut for >5 equally verified graph paths: report `over_k_unranked` pending valid ranking.
3. **Fit and abstain:** route recall, parameter compatibility, field-set completeness and independently calibrated `NO_FIT` are different endpoints. `score > 0` and semantic similarity are **not** authorization or fitness probability.
4. **Execute:** external agent chooses a route and arguments. Trusted host independently validates principal, visibility, snapshot, call schema, destructive policy, executed observations and result provenance. A candidate reference is not a valid execution receipt.
5. **Measure:** registered constraints, safety, required route/field/operation recall, unsupported false admissions, supported false refusals, real final task pass, schema tokens and CPU/RSS. No unseen labels or expected next tool/arguments may enter retrieval or model prompts.

## 4. Comparative protocol and falsification

Use a single pinned native source catalog, identities, principal, K=5, schema-byte/token budget, model, decoding seed, host invoker, and task split. Compare **FULL** and ordinary **lexical SR-5** to opt-in **semantic SR-5**, **typed concept/FieldGroup G5 SR-5**, and **hybrid + independently calibrated disposition**. ORACLE is diagnostics only. Do not substitute a synthetic executor for live provider evidence; freeze an independent author-owned cohort *before* outcome inspection.

| Measurement | Unit / denominator | Failure means |
| --- | --- | --- |
| Route / operation / required field-group recall | Supported query and all required routes/fields; report complete-set coverage separately | A seemingly correct Top-1 can still omit a required second hop or field |
| Supported false refusal vs unsupported false admission | Separate supported and irrelevant/OOD/forbidden counts; include empty menu cases separately | Lower false admission at cost of severe positive recall loss is **not** an unqualified win |
| Task and final-grounding success | Paired independent task, fully executed observed output; failure taxonomy by stage | A provider response or CI-green run is not successful agent completion |
| Safety and provenance | Count unauthorized action attempts **and successful unauthorized effects**, hidden fields, drift, original source validation | Any unauthorized destructive execution or hidden-data disclosure is a blocking failure |
| Efficiency | Actual agent-visible schema bytes/tokens, index build, warm CPU p50/p95/p99, RSS, end-to-end elapsed | Single synthetic GitHub runner timings are not a commercial SLO |

Preregister primary **task-level success** and safety gates; treat changes in route recall, score, or tokens as secondary until their causal effect is measured. Include paired uncertainty and language/catalog strata; fixed thresholds, valid controls, and no hidden-gold route refill. Failed E2 gates remain **VALID_NEGATIVE**, not an opportunity to repair using consumed test rows. Distinguish `E0` synthetic mechanism, `E1` source-exposed development, and `E2` independently authored holdout. Source network timeouts are `SOURCE_FAILURE`, not model misrouting. Abstaining above K and uncalibrated no-fit both require explicit denominators.

## 5. Prior art: what changes our next experiment

| Work and authoritative source | Relevant finding | Concrete transfer / limitation |
| --- | --- | --- |
| [SchemaRouter (Cho, 2026)](https://arxiv.org/abs/2608.21375) | Source-typed schema graph, field projection and provenance with domain-level efficiency gains | Retain original field-aware graph thesis; prior 110-task outcomes do **not** establish current multi-provider agent generalization |
| [ToolRet (Shi et al., ACL 2025)](https://aclanthology.org/2025.findings-acl.1258/) | Heterogeneous benchmark, 7.6k retrieval tasks / 43k tools; conventional IR can underperform on tools | Benchmark retrieval fidelity at source-field and task level rather than trust generic embedding scores; verify license/availability before intake |
| [ToolRerank (Zheng et al., LREC-COLING 2024)](https://aclanthology.org/2024.lrec-main.1413/) | Hierarchy-aware reranking and adaptive candidate truncation for multi/single tool queries | Candidate for **opt-in** bounded rerank after source-authorized eligibility; ranking is not authority or safe abstention |
| [BFCL V4 (Berkeley)](https://gorilla.cs.berkeley.edu/leaderboard) | Function relevance/irrelevance, live and multi-turn/agentic/format categories | Keep original source labels and positive-vs-negative confusion counts; public LIVE evaluated repeatedly is E1, not unseen E2 |
| [ToolSandbox (Lu et al., 2024)](https://arxiv.org/abs/2408.04682) | Stateful tool execution, implicit dependencies and intermediate milestones | Pair field/route exposure with actual multi-step execution, state and task-final success |
| [FAIL-TaLMs (Treviño et al., NAACL 2025)](https://aclanthology.org/2025.naacl-long.149/) | Missing tools and underspecified requests challenge tool agents | Distinguish unknown capability, missing arguments, permissions and provider-unavailable from semantic irrelevance |
| [SafeActBench (Lin et al., 2026)](https://arxiv.org/abs/2610.07753) | Correct final effect does not prove evidence justified a consequential action | Use case-blind policy predicates, time-ordered evidence/argument links, and independently reviewed public action contracts; 393 genuine V1 model trajectories remain unrun |
| [EDGE / KOPA-Bench (Kim et al., 2026 preprint)](https://arxiv.org/abs/2609.05395) | 145 Korean public API multi-step tasks and **live-execution-validated** output→input dependency graph | Closest methodological analog for G5 typed joins; [maintainer repository](https://github.com/dneirfi/EDGE-KOPA) still lists task data, 1,781 EDGE trajectories and model weights as **coming soon** as of audit. Do **not** report an unrun KOPA evaluation or self-synthesize independent gold |
| [ACEBench (Chen et al., EMNLP 2025)](https://aclanthology.org/2025.findings-emnlp.697/) | Normal, ambiguous/incomplete special, and interactive agent tool-use strata | Preregister ambiguity, absent parameters, unsupported no-fit and operation fit separately; compare true model/host outcomes, not only tool-name ranking |
| [tau2-bench (Sierra Research)](https://github.com/sierra-research/tau2-bench) | Task success within policy-constrained, stateful simulated customer-service conversations | Borrow task-level, state and policy violation rubrics; simulation is **not** independently verified real OpenAPI source execution |
| [AgentDojo (Debenedetti et al., NeurIPS 2024)](https://arxiv.org/abs/2406.13352) | Tool-response prompt injection attack / defense benchmark with task-success controls | Adversarially inject lower-trust tool observations and measure authorized action + legitimate completion jointly; never let source content rewrite policy |
| [CaMeL (Debenedetti et al., 2025)](https://arxiv.org/abs/2503.18813) | Trusted control/data-flow enforcement with capability-limited external effects | Separate query instructions from untrusted observation and validate dataflow/authorization; a research security architecture, **not** plug-in performance evidence for SchemaRouter |
| [International Tool Calling (Zhang & Zhu, 2026 preprint)](https://arxiv.org/abs/2603.05515) | Multilingual/international API task evaluation; geography and language matter | Evaluate natural original KO/JA/EN queries against English-only source schema; review benchmark provenance/license first |
| [MCP 2026-07-28 specification update](https://blog.modelcontextprotocol.io/posts/2026-07-28/) | Authorization hardening and cache metadata for enumerated tool/resources | Scope/version/cache eligibility to principal and authenticated source; a cached tool menu cannot itself grant invocation authority |

**Gap after this review:** an independent bilingual/multilingual **source-authored** tool-and-field-level, multi-hop, OOD/forbidden task set suitable for fixed-K paired agent utility is still the central blocker, rather than a new public model score. Do not generate synthetic labels and call them publisher gold.
