## 1. Claim hierarchy

The 0.14 cycle separates several evidence levels that must not be collapsed.

| Evidence level | Work item | Permitted interpretation |
| --- | --- | --- |
| Retrieval mechanics | #418 / #420 Phase A | Recall@K and serialized tool-schema compression on the frozen 23-task surface |
| Small-agent mechanism | #420 B1 | Controlled sanity/reproducibility evidence for Qwen3-0.6B |
| Strong-agent replication | #423 B2 | Evidence that the mechanism is not specific to the small Qwen3 runtime |
| Optimization ablations | #430 and structural K3/K5 | Candidate-depth / representation optimization only; failed candidates are not repaired post hoc |
| Corrective retrieval | #431 | Whether typed observable execution state improves bounded re-retrieval; currently active |
| Large held-out generalization | #432 | Required before a broad heterogeneous-task/language/catalog generalization claim |
| Final-answer factual quality | #424 | Required before claiming preserved/improved factual answer quality, units, or provenance |
| Output-field projection | #506 / #510 | Separate field-level question; current successor runtime qualification is instrument evidence, not projection evidence |

The standing rule is: a DEV or mechanism pass is not a generalization claim, and
an infrastructure failure is not a scientific negative result.

## 9. Authority / verifier architecture

```text
user request
    |
    v
registered OpenAPI / MCP / Python / typed source contracts
    |
    v
typed capability registry  <-----------------------------+
    |                                                     |
    v                                                     |
bounded candidate retrieval / re-retrieval                |
    |                                                     |
    |  model may rank / select / abstain / veto           |
    |  only among registered authority                    |
    v                                                     |
local schema + argument + policy + availability gates     |
    |                                                     |
    v                                                     |
authorized tool execution                                 |
    |                                                     |
    v                                                     |
typed observation / projected declared fields ------------+
    |
    v
final answer
```

The model never creates an executable route, field, argument authority, or
pseudo-capability. Corrective retrieval may change candidate exposure from observable
typed execution state, but execution authority remains local and registered.
